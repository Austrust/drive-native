# drive-core POSIX allowlist (#11 stage 0)
#
# scripts/check-core-posix.sh fails on any POSIX-only hit that is not listed
# here. Scope and grammar are documented in the script header.
#
# Format: <repo-relative path>:<grep -E pattern matched against the hit line>
#
# Keep entries narrow: prefer a token specific to the allowed construct (for
# example `libc::E` for errno construction) over a pattern that matches the
# whole file. Add a reason plus the migration step (see #11 design report
# sections 3.1/3.2) above each group. Delete entries as the migration lands.
#
# Deliberately NOT listed: *_tests.rs modules (out of scope by file name),
# std::fs::symlink_metadata / FileType::Symlink (cross-platform), and fsync of
# regular files (works on Windows).

# --- Module-level std::os::unix imports (Step 1 FileIdentity / Step 3 SecureIo) ---

# read_at on drafts uses FileExt::read_at; moves to SecureIo::read_at.
crates/drive-core/src/drafts.rs:os::unix::fs::FileExt
# ReadHandle::read_at is already cfg(unix)-gated; replaced by SecureIo.
crates/drive-core/src/state.rs:use std::os::unix::fs::FileExt;
# #60 storage bounds: build the CString for statvfs(2) from the profile path.
# Filesystem-space accounting is a host capability, not a core business rule;
# moves to the platform layer with SecureIo (Step 3) and is deleted then.
crates/drive-core/src/state.rs:use std::os::unix::ffi::OsStrExt;
# consume_startup_pause reads uid/mode and opens with O_NOFOLLOW|O_NONBLOCK;
# moves to SecureIo::open_private_no_follow + PlatformSession owner check.
crates/drive-core/src/task_control.rs:MetadataExt|OpenOptionsExt
crates/drive-core/src/task_control.rs:custom_flags\(libc::O_NOFOLLOW
crates/drive-core/src/task_control.rs:libc::geteuid
# preview_storage_safe uses O_DIRECTORY|O_NOFOLLOW and AsRawFd; the whole
# preview module is planned to become cfg(unix)-gated (FUSE-only feature).
crates/drive-core/src/preview.rs:use std::os::unix

# --- libc POSIX APIs other than errno (Step 3 SecureIo / platform layer) ---
# #60 storage lifecycle bounds use statvfs(2) for three decisions: the bounded
# default cache budget, the bounded drafts quota and the pre-VACUUM INTO
# migration-backup headroom check. Disk-space/free-space queries are host
# capabilities rather than core business rules, so they move to the platform
# layer (SecureIo::filesystem_space / PlatformSession) with the rest of Step 3;
# delete both entries with that migration. They are called once at store open
# (sizes are memoized), so no hot path depends on the libc call.

crates/drive-core/src/state.rs:libc::statvfs\(
