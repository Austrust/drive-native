# 初始化扫描的普通文件变化收敛

本改动让初始化/恢复扫描期间的普通文件变化通过局部目录重查收敛；目录结构或权限不明确时仍走原整树重试。它不提供逐目录提前发布、本模块自身不更改首次 seed 的取得方式；整合后的起点见[当前水位](SNAPSHOT_WATERMARK.md)，不是 Personal_Sync 真实 NAS 性能已验证的结论。

参考项目内 Windows 工作链路审查（2026-11-01）：保留目录协调与事件位置提交的分离。这里的具体局部重查算法是本项目实现，不声称已恢复 Windows 同等内部算法。

## 提交边界

`recovery_snapshot` 完成原始整树枚举后，将候选交给私有 `native_snapshot_reconcile`。来自 `scoped_events` 的事件仍经过所选根身份检查。候选、索引及中间接收游标仅在当前异步调用内存在；不改数据库、不发布部分目录、不清理缓存。

普通文件事件根据事件源父、移动目标父以及候选内该文件目前父目录确定重查集合。父身份必须存在、为已枚举可访问目录，且其候选路径必须与事件路径的父部分吻合。对这些父调用原有原生 `list_dir`，沿用其分页、身份/版本、返回格式和传输检查。

所有局部列表收齐并校验后，只替换这些父的直接文件集合。目录必须与原候选逐项一致，包括身份、名称、版本和元数据；子树不重新枚举。先移除所有被重查父的旧文件，再加入新文件，支持跨父改名和删除后的同名新身份，且不因处理顺序制造临时冲突。跨未重查父的身份碰撞、重复名/ID、缺父、目录变化均不能通过。

每轮重查后必须从刚收到批次的下一事件位置继续 fence。空但推进的批次继续读取，直到静止空批才返回完整候选及该位置。重查期间的后续文件变化会触发新一轮局部重查；新目录、目录移动、ACL 等歧义会丢弃整个私有候选并回到原有最多三次的安全重建。后续网络/格式错误或取消不会返回已修改的中间候选。既有 `snapshot_unchanged` 研究接口保持原语义。

## 保守回退与预算

- 目录事件（包括 Modify）、根事件、symlink、新增/消失/修改的目录项、不可访问父、源/目标路径不匹配、身份冲突：原整树回退；根删除/替换仍明确失败。
- 局部目录 12290 权限拒绝：回到完整枚举的 ACL 排除路径；传输和其他服务器错误保持原错误类别。
- 每次候选收敛最多 4096 事件页、4096 局部列表调用、200 万事件、500000 个最终节点及一批被接受的局部回复节点。900 秒绝对 deadline 包住每次 fetch/list future，过期取消整个分页调用；同步 CPU 工作在边界检查，不声称硬实时抢占。底层列表 API 先构造完整列表才返回，其单次原始返回仍受原有列表上限约束，这里不是进程总内存上限。
- 累计页数、请求数、时间和事件数不因重查轮次重置。持续变化耗尽预算会失败，不发布未验证快照，也不无限重扫。
- 一次按身份/父构建索引并以 O(N) 根遍历检查图和深度；只为实际受影响父构造路径，完成时不做全树排序。局部列表移入候选，不额外克隆所有新文件。没有周期全树扫描；最终仍一次性调用现有事务安装逻辑保护未上传修改。

## 回归与未验证边界

新增模拟回归覆盖重复内容更新、跨父改名、第三父位置的历史改名、当前列表面对后继旧事件不降级、删除/同名替换、移动进出范围、目录/权限回退、新目录或目录元数据变化、重复名/ID、跨未查询父碰撞、中途错误、根丢失、非推进游标、共享页预算、deadline 取消及最深合法文件。真实本地 Store 回归同时检查拒绝安装不推进游标，以及成功安装后未上传草稿仍可重启恢复为冲突。

2026-11-01 隔离回归 `snapshot-convergence-005`：`cargo test --locked --offline -p drive-core --all-features` 的 25 个 suite 合计 **307 通过、0 失败、1 忽略**，包括上述 18 项新增测试。忽略项为已有显式容量测试，本轮未重复运行。首次 `001` 因 Cargo 路径不存在在编译前失败，已保留记录；修正为项目离线工具链后 `002`–`005` 均成功，最终结果以 `005` 为准。

测试仅使用模拟事件/列表及本地状态，没有 NAS 连接或原基线操作。实际调用次数、Personal_Sync 冷启动耗时、目录事件频率与服务端分页一致性仍须真实隔离验证；持续目录变化仍可能触发整树重试。运行层整合、全客户端构建和新安装包由后续交付门禁验证，本记录不替代其结果。
