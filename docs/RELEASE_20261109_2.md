# Drive Native .20261109.2：错误与恢复模型、空间释放、通知与排除规则（#2 #6 #8 #9 #10 #11 #14 #18 #19 #50 #53）

开发版 `0.1.0~dev20261109.2`，面向 Ubuntu 24.04／Mint 的后续试用。发布源提交为 `73ab2b33d3b0e5c1a1c6b986988af38100a66c55`（PR #55 合并 `integration/fixes3` 后的 `main`，包含发布准备提交 `be25869`；本包即从该提交的 `git archive` 树构建），数据库 schema29、IPC21。本版在上一版 #21–#34 的并发与锁修复之上，解决了上传权限不确定后的永久待定、释放空间无进度与残留、托盘状态过期、已绑定目录无恢复出口等用户可见问题，并引入提交结果诊断、自动恢复、按任务排除规则与 Windows 平台化第一步。

## 本次改善

- **提交结果与诊断（#9 TB1/TB2）**：新增 `CommitOutcome`（Confirmed／Conflict／UnknownRetryable／UnknownFatal）与 12 类 `CommitCategory`；schema 升到 **29**，为 `operations`／`namespace_ops`／`transfers` 增加 outcome、category、last_error、next_retry_at 与 updated_at，增加 `schema_migrations`、`recovery_runs`、`platform_state_changes`、只读 `commit_diagnostics` 视图与一次性回填；upload／rename／mkdir／remove／replace 五条写路径在同一事务记录诊断，`GetOverview` 增加 additive `commit_diagnostics{open_unknown,needs_attention,items[]}`，且同版本视图在打开旧 v29 库时自动修复。IPC 保持 21。
- **自动恢复（#10）**：把 `rescan_later`／`merge_mode`／快照与游标缺口归为 `RecoveryRequired`，与可重试、致命错误分开；bridge 单飞恢复循环最多 3 次，按 2/5/10 秒与 0/5/15 秒两档退避驱动重建快照或局部重查，状态写入 v29 `recovery_runs`；只有认证、证书、根失效和恢复耗尽才需要人工处理。`GetOverview`／`GetIssues` 增加 additive `recovery{state,cause,attempts,next_retry_at,revision,attention}`，恢复中重查返回 `reconnecting`，断连恢复后主动刷新已打开目录。
- **释放空间与回收（#19）**：批量释放改为可取消的后台任务，`GetReleaseJob` 回报 done／total／released／skipped／protected／reclaimed_bytes，GUI 显示“正在释放 n/m · 已回收 X”；`ReleaseSpace` 保持原同步语义并 additive 增加 `skipped`；`blob IS NULL` 的 online-only 文件如实返回 skipped 并撤回其失败的下载意图；GC 清理 `deleted=1` 节点的悬空 blob 指针且不再把 deleted 节点计入 keep 集，live／conflict／journal（operations、namespace_ops 等）引用仍受保护；服务重启后 GUI 停止轮询并提示重试。
- **上传终态与放弃（#14）**：只读核对预算（5 次，10/30/120/300 秒退避）耗尽后，上传进入终态 `abandoned`，不再计入 `pending_operations`／调度／队列未完成，也不写后台错误；新增 additive `paused_uploads` 计数、问题中心 `can_abandon_upload` 与 D-Bus `AbandonUpload(id, token)`（token CAS，仅删除本地未发送文件，绝不向服务器发删除）；本地删除与放弃会作废该节点残留的 pending／uncertain 上传；重新核对会把 abandoned 重新武装为 uncertain 并重置预算；abandoned 的 blob 受 GC 保护。
- **冲突恢复（#6、#54）**：安装快照后与成功的 mkdir／rename 提交后，按严格谓词在同一事务清除陈旧目录 conflict 标志；真实冲突保留。已绑定目录被服务器删除后，问题中心提供 keep-local／keep-remote 恢复入口（keep-local 重命名本地子树、keep-remote 仅在本地无内容时可破坏性执行），补齐冲突恢复回归。
- **排除规则（#50 P1–P4）**：profile 新增可选 `exclude_patterns`（Rust regex 预编译、保存时校验并提示 pattern 与编译错误）；匹配目录的整棵子树在初始化时不导入、不下载，在 FUSE lookup／readdir、`GetDirectory`／`GetStates`、事件处理中完全隐藏（统一 ENOENT），本地写入与上传／下载／缓存调度防御性拒绝；规则变更重启后本地隐藏并清理已导入／已缓存内容（复用 GC 回收，不向远端删除，规则移除可恢复）；修复“初始化 preview 阶段带排除规则时挂载失败退出”的回归；GUI 增加规则编辑器。
- **通知与托盘状态（#2 2a、#53）**：托盘不可用时通过 freedesktop D-Bus Notifications 投递问题通知（`Notify` 用 jeepney 显式签名，点击 `ActionInvoked` 定位到发起的挂载；缺失依赖时静默降级为托盘）；提交状态水位前进时刷新 overview，托盘“需要检查”徽标与导航计数不再长期过期。
- **硬链接语义（#18）**：`link(2)` 返回 `EOPNOTSUPP`／`ENOTSUP` 而不是 `EPERM`，工具可按标准语义降级为复制或改名；文档说明 Synology Drive 无硬链接身份，不做伪硬链接。
- **初始化可响应性（#8）**：补齐第 4 条验收的可重复测试：真实初始化进行中并发 64 次 `GetDirectory`／`GetStates`／`GetOverview`／`GetInitialization` 查询，p95 ≤ 500 ms 且可证明查询期间有目录提交；无运行时行为变化。
- **平台化第一步（#11 step0/1）**：新增 `scripts/check-core-posix.sh` 门禁并接入 `scripts/verify.sh`（基线 110 命中／66 文件全部 allowlist，默认模式 0 violation）；新增 `docs/WINDOWS_PORT.md` 三 trait 设计与 CFAPI 范围；core 新增 `PlatformFileId`＋`FileIdentitySource` 契约＋`StoreFileIdentity` Linux adapter，u64 接口、schema、IPC 与 FUSE 行为不变，v30 `platform_file_ids` 与 Windows adapter 留到下一步。

## 验证和升级

发布包由 `dpkg-buildpackage -b -us -uc -j4` 在干净 `git archive` 树上构建（测试未关闭）：`cargo test --workspace --all-features --locked` ****1322 通过／0 失败／67 忽略**（69 个 test 结果行）**，GUI ****27 套 333 项**** 通过；`scripts/verify.sh` 退出码 0，lab `--simulate` 报告 `passed=true`、`LocalComplete`。包内容核对通过：三个 native 二进制、GUI onedir、`/usr/bin/drive-native` 包装、4 个 systemd user units、Nemo／Nautilus 扩展与 gio probe 齐备；`SOURCE_COMMIT` 与 `BUILD_VERSION` 与源一致，包内没有 `.git`、凭据或实验数据。

schema 由 28 升到 29：`operations`／`namespace_ops`／`transfers` 增加提交结果与诊断列，新增 `schema_migrations`／`recovery_runs`／`platform_state_changes` 与 `commit_diagnostics` 视图；28→29 为唯一迁移路径，`Store::open` 迁移前用 `VACUUM INTO` 生成 `state-before-v29-*` 备份。FSD 与 worker 必须成对更新，旧程序不能读取新 schema。升级时先在任务界面选择“应用后台更新…”，按提示保存并关闭正在编辑的文件；升级会暂停并正常切换后台，保留任务、未上传修改和同步历史。不要通过清缓存处理升级或同步错误。

本构建机没有可用的 chroot/debootstrap，因此没有执行真实 dpkg 安装／升级／卸载验证；本版对安装流程的结论止于包内容与元数据层，真实 Mint／Cinnamon 桌面验收也未执行。kernel FUSE 测试需显式串行并设置 `DRIVE_NATIVE_FS_DIAGNOSTICS=1`。
