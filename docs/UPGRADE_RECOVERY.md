# 暂停、升级与恢复

本文说明源码中的升级机制及实际验证。当前20261101 `.4 → .5` 为同schema20升级：暂停接管、旧ELF实际挂载读取及两份pending编辑／草稿保留见[包验证010](validation/native-package-010/REPORT.md)。未知提交和活跃候选升级不在本安装夹具范围；未安装旧包降级。历史 `.3 → .4` 见[包验证009](validation/native-package-009/REPORT.md)，schema迁移见[008](validation/native-package-008/REPORT.md)和[007](validation/native-package-007/REPORT.md)。正常升级不要求清缓存，最终状态以[DELIVERY_GATES.md](../DELIVERY_GATES.md)为准。

## 正常升级

1. 保存并关闭挂载中的文件，在对应任务窗口暂停同步。暂停保留挂载、本地完整内容及未上传编辑。
2. 安装更新包。仍在运行的旧后台不会因为安装路径被替换而自动变成新进程。
3. 打开新版 GUI，在任务窗口选择“应用后台更新”。GUI 会确认任务身份，暂停同步、保存启动暂停意图，然后请求旧后台正常停止。
4. 旧进程退出后才启动已安装的后台。GUI 继续确认：D-Bus owner 已更换、任务身份一致、挂载已就绪、状态为暂停、进程执行文件与当前安装文件的 inode 一致。
5. 确认任务状态和文件后，手动恢复同步。

正常升级不要求清除缓存、删除数据库或重新建立任务。关闭 GUI 本身也不会停止挂载。接管期间路径会经历正常卸载、重新挂载，因此应先关闭使用该目录的应用。

## 暂停如何保留

新后台把每个任务的暂停状态单独保存在 SQLite 中。只有持久提交成功，D-Bus 的 Pause/Resume 才返回成功；启动或解锁不会自动取消已经保存的暂停。

历史 `20261031.3` 后台的 Pause 只保存在内存。首次从它迁移时，新 GUI 会在旧 Pause 确认后、停止旧进程前，原子写入该任务的 `startup-pause-v1.json` 并同步文件和目录。新后台验证标记的任务身份、属主、私有权限及普通文件类型，将暂停状态提交到自己独占的数据库后消费标记。GUI 不直接修改旧后台正在使用的数据库。

直接终止历史 `20261031.3` 进程再启动新版，无法凭空恢复旧进程的内存暂停意图。首次迁移应使用新版 GUI 的接管操作。新后台之间的后续重启依靠已经持久保存的暂停状态。

## 后台组件需要成对切换

文件系统后台与网络 worker 使用内部 IPC。运行中的新后台会保留启动时匹配 worker 的可执行文件句柄；即使安装路径被替换，重连仍使用原来配套的 worker。正常退出后由新后台使用新组件。

如果启动时无法取得 worker 镜像，网络工作进程明确拒绝启动，不回退到后来出现的路径；本地状态仍然保留。重新安装完整组件后，通过正常退出和启动恢复，不需要清理用户数据。

## 本开发分支的存储迁移边界

已发布 `.1` 使用 SQLite schema18、`.2` 使用schema19；20261101 `.3` 增加与代次绑定的游标重置许可，`.4` 保持数据库版本20。Store 打开旧版本数据库时先使用 SQLite `VACUUM INTO` 保存包含已提交 WAL 内容的一致备份，再迁移。新版本数据库由较旧二进制拒绝打开，不能通过手改 `user_version` 或清缓存绕过。备份恢复也不能自动涵盖升级后新增的未上传编辑，必须保留完整用户状态。

此前同schema回退验证不证明 schema19 或20可降级。真实旧二进制拒绝、18→19暂停迁移及未上传数据保留已通过[包验证007](validation/native-package-007/REPORT.md)；未承诺任意旧版本可降级。当前源码内部 IPC 升至17，须切换配套 FSD／worker；详见[进度接口](INITIALIZATION_PROGRESS.md)及[持久候选基础](INITIALIZATION_PERSISTENCE.md)。当前Service已接入生产候选调度；schema19→20暂停接管、迁移备份、旧ELF拒绝以及重装保留两份pending编辑与草稿已通过[本批包验证008](validation/native-package-008/REPORT.md)。安装夹具没有提交结果未知的操作，相关runtime回归不等于该类升级已验证。逐目录提前可见仍未实现。

## 失败时的处理

| 情况 | 行为与处理 |
| --- | --- |
| 暂停提交或启动标记持久保存失败 | 不停止旧后台。检查本地空间和权限，重试保存。 |
| 旧后台迟迟没有退出 | 不强杀，不启动竞争后台。先关闭打开的文件，再检查该任务状态。 |
| 新进程启动了，但身份、暂停、挂载或版本未确认 | 显示接管尚未确认；不会仅凭进程创建成功宣称完成。检查该任务及其用户服务日志。 |
| 标记是符号链接、FIFO、身份不符或权限不合规 | 拒绝标记；FIFO 检查不等待写入者。保留数据，诊断具体原因后处理。 |
| 网络断开或 worker 重启 | 与后台升级分开处理；不应通过删除本地状态恢复网络连接。 |

不要把清缓存作为升级失败的修复步骤：其中可能包含未上传草稿。需要回退时应先正常停止该任务，保留完整状态，再检查目标版本的数据库兼容性；本文不承诺任意版本之间都可降级。

## 已验证与仍待验证

合成、隔离的 Qt/D-Bus/FUSE 测试已经验证旧 `.3` 到修复组件、修复组件再次接管时的暂停、游标、完整缓存、待上传操作和草稿正文保留；旧进程正常退出、新进程身份与安装 inode 匹配。实际 Qt 控制器在完成回调前自行确认接管条件。单元测试覆盖持久化拒绝、错误任务、FIFO、pidfd 生命周期及错误状态不得报告成功。

历史 `20261031.4` 已完成实际安装文件与自定义managed systemd服务的组合验证、包回退/清除重装和草稿保留；该接管使用同版源码控制器，另行验证已安装GUI启动。仍需安装失败恢复、生产钥匙环启动链路及正在执行本地fsync时的退出故障测试。WSL的外部挂载命名空间可延迟FUSE退出，本次失败及独立复测见包验证。Mint桌面与长期验收继续开放。

上述 `20261031.4` 结论保留为历史；后续已发布 `.1` 的隔离包生命周期还验证了暂停接管与未上传数据保留，具体数量和范围以包验证006为准。当前schema20迁移采用包验证008的独立结果；已有隔离Ubuntu环境不代表干净OS或Mint安装，生产钥匙环及升级故障门槛继续保留。
