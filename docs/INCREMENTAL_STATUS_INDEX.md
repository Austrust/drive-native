# 增量目录状态：纯聚合核心与后续接口

2026-10-31。本批基于 `9ed1b23` 的[事务变化日志](STATUS_CHANGE_JOURNAL.md)，实现一个独立的纯聚合模块；设计依据为 [P1 §C](P1_ARCHITECTURE.md) 和现有 [desktop::entry](../crates/drive-runtime/src/desktop.rs) 状态规则。代码为本项目实现，不包含服务器数据或官方客户端代码。**运行中的 desktop 查询未切换，完整树索引和性能验收尚未完成。**

## 本批已经实现的接口

[status_aggregate.rs](../crates/drive-core/src/status_aggregate.rs) 不持有 Store、路径、文件句柄或后台线程。

| 接口 | 输入与保证 |
| --- | --- |
| `leaf(&LeafFacts)` | 已投影的持久状态、继承 pin、内容可用性、活跃下载数量、下载错误；返回完整状态摘要或明确的未确认/无效输入错误 |
| `DirectoryAggregate::set_child(id, Option<ChildState>)` | 添加、替换、移除一个直接子项；相同输入不变更，预算或输入拒绝保留旧贡献 |
| `DirectoryAggregate::summary(own, inherited_pin)` | 从固定状态计数和有序错误索引取摘要，不遍历 children，更不访问 SQLite、正文或后代 |
| `accounted_bytes()` / `retained_allowance()` | 分别报告存活贡献的逻辑余量与保留槽位的余量；供未来全局预算管理，均不是进程 RSS |

状态包含 conflict、pending_upload、下载/更新失败与重试、updating、downloading、pinning、pinned_complete、local_complete、mixed、online_only。`pinned`、`offline_available` 和错误详情分别保留；没有用“完整/不完整”两态代替原规则。目录只累计直接子项的摘要，再向祖先传播，不能把整个后代集合重复输入。

叶节点的冲突/本地待上传优先于下载状态；活跃下载覆盖失败标签但保留错误详情。多个版本仍在下载时，用数量而非一个可被先结束任务清除的布尔值。空目录离线完整；父目录固定不由某个已固定子项反向推导。未知子项保持占位并阻止生成完整摘要。数据库声称本地完整而实际内容已缺失时，返回需重新投影的错误，不能继续报完整。

目录按现有优先级维护各状态计数，移除最高优先级子项后可以立即选出下一项。错误代表项先取最大 attempts；同次数时取最大直接子项数字身份，因而与输入顺序无关。现有批量算法的同次数选择依赖 HashMap 遍历顺序，这一确定化是明确的差异；将来 oracle 应核对合法的同次数代表集合，其他字段精确比较。数字身份应由后续树拥有者稳定映射，不能用路径哈希冒充文件身份。

单个子项更新为哈希表操作加错误索引 O(log 直接子项数)；查询只检查固定标签数量并读取有序索引末项。当前模块没有自动祖先传播、路径解析、ACL 筛选、事务发布、生命周期或增量来源订阅，测试中的移动也是调用者分别更新两个父对象。

## 下一层的最小可实现接口（尚未实现）

保持 Store 是唯一持久权威，派生索引只服务展示，不参与上传/删除授权。建议先完成下表的提交投影和变化唤醒，再接入整树拥有者，最后替换 desktop 查询。

| 接口概念 | 契约 |
| --- | --- |
| `capture_status_delta(after, budget)` | 在 Store 串行边界内选择已提交 journal 水位，读取至该水位的失效集合，并投影当前受影响 atom 与旧新同名桶；返回完整 `ProjectionBatch` 或 `RebuildRequired`，不返回可发布的半事务 |
| `ProjectionBatch {db_epoch, from, through, atoms, affected_buckets}` | atoms 包含稳定身份、有效父/名、可见性、类型、own status、局部 pin/overlay、下载错误、内容版本/可用性。未改变的旧父关系可从已发布索引取；日志保留所有旧新父/名，覆盖创建后又移动等情况 |
| `TransientSnapshot/Delta {epoch, seq, flights, availability}` | fsd 级瞬态来源；下载按身份/版本及生命周期 token 记录，内容核验独立记录。不能依赖某个 RPC 连接的计数或重置的 revision |
| `IndexOwner::apply(batch)` | 单写者；先预留全部变更额度，更新路径桶、可见关系、叶贡献及祖先，原子发布同一代。拒绝或 gap 进入未确认状态，不发布一半的新父/旧父 |
| `PublishedStamp {db_epoch, db_seq, transient_epoch, transient_seq, generation}` | 查询和通知共同使用；路径解析、摘要、ready 标志来自同一发布代次 |
| `query_many(paths, limit)` | 有界请求，从已发布路径索引解析，返回有限摘要；不拿 Store、打开正文或临时重建树。未就绪返回明确 local-state 错误，不以全树扫描作日常回退 |

变化日志是当前状态的失效提示，并非历史 atom。消费第一个页面后读取“当前 atom”，再按下一页处理历史位置，不能逐页发布。最简单正确实现是在一次 Store 串行边界中收集至捕获水位并投影有限失效集合；超过批次预算就重建。若以后要分块释放锁，须使用固定数据库快照，或验证水位并重试，不能把多个时刻的 atom 拼成同一代。

所有 Store 调用边界都需要提交后唤醒，包括返回 `Err` 的边界：草稿方法可能先提交 dirty 再发生文件 IO 错误，快照安装可能先提交再在后续更新失败，逐个缓存释放也可能中途失败。触发器已保留这些提交；消费者应比较调用前后的**已提交语义水位**并在释放写入边界前标记待处理/唤醒，不以最外层 `Ok` 为条件。回滚后水位不变，不产生语义变更。必须明确覆盖所有 Store 锁入口，采用统一 guard/执行包装；不能只在 GUI/RPC 成功响应处通知。

TEMP journal 插入、真实 prune、预算元数据写入仍计入 SQLite `total_changes`。本批同预算 setter 与重复 prune 都在写入前早退；改变预算或真正回收仍可影响旧 `local_revision`。新消费者不得以 `local_revision` 作为提交 stamp，也不得“查询→清理日志→旧粗通知→重建”形成反馈。唤醒依据 journal epoch/sequence/gap，桌面信号依据发布后的 generation；消费到同水位且没有瞬态变化应完全不写、不发信号。

## 重建、一致性与锁顺序

首次启动、epoch 变化、gap、未知关系或预算拒绝，只允许一个重建者。候选重建要有节点、字节和时间预算。若使用独立 SQLite 只读连接，应在 Store 写锁保护的短临界区内建立并实际读取以固定 WAL 快照，同时捕获 journal 水位；仅执行延迟 `BEGIN` 并不固定读取时刻。TEMP journal 只能由原 Store 连接读取，不能让只读连接查询它。随后分块读取该固定主库快照，补齐期间的 journal 和瞬态变化，再发布。超过保留范围丢弃候选并明确重试，不跳过 gap。

提交后未消费期间需有 pending/readiness 标志；旧快照最多作为明确未确认的展示，不能继续宣称当前已同步。ACL 收回还必须立刻使相关展示失效，避免发布滞后继续暴露已撤销路径；实际 FUSE 访问仍由现有 Store 权限检查约束。若当前桌面协议无法表达未确认，先返回已有明确错误，扩展状态时同步 GUI/Nemo 兼容测试。

当前 [bridge](../crates/drive-runtime/src/bridge.rs) 的缓存维护/释放持有 flights 锁后才取 Store 锁。新路径不得反向持 Store 等 flights。快照可按既有 flights→Store 顺序短暂捕获两个起始序号；后台投影与父链计算在锁外完成。禁止在这两个锁内阻塞发送有界通道或等待桌面读者；try-send 溢出记录可检测的 gap 并合并唤醒。查询只读已发布索引，单写者发布锁内不做 SQL 或正文 IO。

## 瞬态、可见关系与内容的覆盖

1. **下载生命周期**：在真实 flight 插入/移除处产生序号，开始、取消、成功、失败和异常清理都覆盖。新旧版本同时存在时分别计数；重复完成或旧 token 完成不能清掉新 flight。重连不清空 fsd 的瞬态 epoch；工作进程更换后按实际 flight 生命周期结算。完成提交先更新可用性/持久状态，再清除 active；发布不能短暂产生“已完成但无内容”的状态。变化队列溢出重新捕获 flight 集合及序号。
2. **ACL 与可见图**：复用 [desktop_status_seeds](../crates/drive-core/src/desktop_status.rs) 和文件系统查询的有效可见性规则，包括祖先 access_denied、deleted、local_creations 同名遮蔽和 namespace_overlay。不能只监听 nodes。权限变更更新受影响子树及旧祖先；解除隐藏重新投影，不作为新增 NAS 文件或本地删除。
3. **移动与替换**：从旧父删除贡献、在新父插入新贡献，更新同名桶与被遮蔽身份；旧路径映射与新摘要必须同代。移动到不同继承 pin/overlay/ACL 的父下要重新投影受影响后代；目录固定/取消固定同样可能遍历子树，不能宣称所有变化都仅 O(深度)。普通单文件状态改变只更新自身和祖先，摘要相同时停止上传播。
4. **内容可用性**：来自成功发布、草稿持久化、释放、启动核验及真实 IO 缺失事件；失败下载保留旧完整版本。索引不能以 blob 字段非空代替实际可用性。外部删除缓存没有必然的 SQLite 变化，启动/后台核验和已打开操作报错须送入 availability 序号。未核验时显式 unknown；查询不访问正文。核验结果携带身份/版本/内容 token，过期结果不能覆盖新版。

## 内存预算与发布方式

当前纯模块的 budget 限制存活直接子项数和固定载荷余量。HashMap 删除后通常保留容量，`retained_allowance` 另报历史槽位；空表主动释放。该余量不是分配器证明或全局额度，不能把每个目录预算乘以目录数就宣称总内存受控。

树拥有者必须有统一全局预留：身份/路径字符串、父边、同名桶、贡献表、错误索引、空容器、瞬态集合、未处理批次、journal、重建候选和仍被读者持有的旧发布版本都计入。变更前预留、实际 drop 后归还；拒绝不能留下半个移动。容器增长和删除后的保留容量需要显式追踪/回收，不能只统计 live rows。本模块的会失败输入预检只保证自身贡献不变，不提供跨目录事务或 OOM 恢复。

不建议每次发布 clone 全树。第一版可用单写者＋短发布读写锁，批次在局部 staging 中验证，锁内只安装预备变更，查询有批量上限；若使用分块不可变结构，旧块与候选块也必须纳入预算，不能把 Arc 引用视为免费。具体选择需通过混合查询的锁等待与内存峰值测试后确定。

## 本批验证及接入门禁

WSL Ubuntu 24.04 独立 `status-aggregate-001`：状态专项 22 通过（14 journal + 8 aggregate），core 全功能 183 通过，均 0 失败、0 忽略。使用独立 target、2 jobs，负载记录到既有 P0 时间轴；只用于功能验证，耗时不作性能结论。本批没有 NAS、桌面、FUSE、workspace 全量或压测。

[聚合单元测试](../crates/drive-core/src/status_aggregate_tests.rs)覆盖全部标签优先级、删除后降级、空目录、固定与可用性独立、未知内容、多个活跃版本数量、错误代表项更替、错误清除、重复输入、预算拒绝不变、旧新父贡献与嵌套 mixed。[journal 测试](../crates/drive-core/src/status_changes_tests.rs)新增同预算 setter/重复 prune 不增加粗通知的回归。

下一批先实现提交投影/统一唤醒，保留旧批量路径作 oracle；完整索引接入前必须补：

- 随机状态序列与旧批量结果比较；除已说明的同次数错误代表项外逐字段相等，包含父链继承、遮蔽、ACL、原子替换和失败回滚。
- 外层返回 Err 但已提交、事务/保存点回滚、批次横跨日志页面、重复唤醒、gap/epoch 和构建中写入；发布不能混合事务/快照。
- 双版本 flights、取消部分读者、异常退出、重连、瞬态溢出、过期内容核验；终止一个旧任务不能结束新任务状态。
- 全局预算不足、候选+旧代同时存活、长路径/宽目录、权限撤销后查询、正常单文件更新仅触及身份和祖先。
- 旧/new 相同数据与负载、独立固定窗口的 P1 状态延迟、混合目录负载、CPU、RSS 峰值与队列/句柄上界。通过这些门禁前不替换当前 desktop 或纳入性能达标声明。
