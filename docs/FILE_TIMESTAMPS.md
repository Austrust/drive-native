# 文件时间与原生写回

本文记录 schema23 / IPC20 引入的文件时间契约。历史[包013](validation/native-package-013/REPORT.md)和 [Lab004](validation/native-lab-004/REPORT.md)核对了内核调用、升级及原生写回后的时间与内容；这些结果不作为新 ACL 候选的实测证据。当前权限叠加与验证见 [#7 报告](FIX_7_REPORT.md)，发布基线见 [.9 说明](RELEASE_20261103_9.md)。

## 文件 mtime

FUSE 接受文件 `UTIME_NOW` 和明确的修改时间。原生上传字段由官方 Linux 客户端的 `PrepareMtime` 路径恢复：完整内容上传附带显式秒值，使用无引用形式的 `mtime` 对象。协议值为无符号 32 位 Unix 秒；本客户端声明一秒时间精度，纳秒向下归一到整秒，负值返回 `EINVAL`，超出范围返回 `EOVERFLOW`。未指定的字段不修改。

时间修改沿已有内容写回流程执行：缺失正文先按需下载，修改本地草稿的时间，再生成持久上传快照。复制草稿正文时同时保存时间，避免新文件的创建时间覆盖用户请求。操作与其显式时间意图在同一 SQLite 事务中入队；系统调用成功表示本地已持久保存，服务器确认后才显示已同步。这条路径需要完整内容上传，不是仅修改服务器元数据。

逐动作权限下，本地 `utimes` 准备与修改按 `Setattr` 检查；普通写入/截断仍按 `WriteContent` 检查。
若 Setattr 允许而 WriteContent 拒绝，mtime 可以本地持久化、正文保持不变，但现有完整内容上传仍被 WriteContent 门禁阻挡并保留 pending。
元数据专用的远端 mtime 写回未实现；本地成功不表示服务器时间已经更新，也不会借 Setattr 许可绕过内容上传拒绝。

打开的句柄继续使用原工作草稿；时间变更增加本地修改代次，旧上传回执不能清除之后的修改。重命名替换记录源文件时间，并在目标上传确认时核对。已解除目录项的打开文件可以更新本地时间，但不为被删除的路径生成上传。

原生上传回执本身不足以确认时间。上传后目录核对必须同时匹配身份、版本、大小、内容校验值及请求的 mtime；未知提交的只读核对也检查 mtime，并在正文验证后再次核对元数据。相同内容但错误时间不能被标记已同步。

## atime 与边界

访问时间是本地持久属性，不参与服务器上传。只设置 atime 不下载正文、不创建上传任务；数据库保留秒和纳秒，内核按声明的文件系统时间精度协商。轻量 POSIX 查询在同一个 SQL 投影中读取该字段。

目录 mtime 仍返回 `EOPNOTSUPP`：尚无经过验证的目录元数据修改契约。组合请求先验证支持范围，避免目录 mtime 被拒绝却先修改 atime。普通文件 `touch`、`cp -p` 和 `rsync -t` 所需的文件时间路径已接线；目录时间、所有权转移和协议范围外的时间不作成功承诺。

## 升级与验证

schema 23 增加本地 atime 和上传时间意图表，升级前沿用一致数据库备份，旧程序拒绝较新 schema。已有 pending、inflight、uncertain 操作没有时间意图时保持旧确认语义，不从缓存文件时间反推曾经发送的参数。旧替换任务的缺失字段也保持 `None`。

针对性验证入口：

- [核心时间与迁移测试](../crates/drive-core/tests/timestamps.rs)：持久草稿、回滚、旧不确定提交、身份绑定、替换与打开后删除。
- [FUSE 内核测试](../crates/drive-fs/tests/timestamps.rs)：实际 `touch`、`cp -p`、atime-only、遗漏字段与明确拒绝路径。
- [回执核对测试](../crates/drive-runtime/src/timestamp_upload_tests.rs)：错误 mtime 保留为待核对状态，后续只读确认不重复上传。
- [受限实验 peer](../crates/drive-runtime/examples/native_validation_peer.rs)：只读 `stat` / `stat_copy` 仅检查本轮唯一实验子目录里的固定文件；不开放任意路径。

真实验证应在内容更新与离线读取流程后设置固定秒值，再用独立 peer 检查服务器时间、身份与内容未变化。该验证和最终安装包结果由本轮发布报告记录。
