# 从当前事件水位开始选定子目录初始化

本轮取消可直接核对当前根元数据的子目录在首次初始化前从事件位置 0 读取全部历史的前置步骤。当前根元数据来自原生父目录列表，必须同时匹配选定的 file_id、node_id、名称、目录类型和非删除状态；不会只凭路径接纳同名替代目录。

## 协议与提交顺序

Windows 条件路径静态确认 `get_max_sync_id`、响应 `max_sync_id`，以及先处理相关工作、再保存事件检查点的边界。请求使用标准会话封套，并携带 `view_id`、`root_node_id`、`root_node_path`、`path`、`server_id.restore_id`。根上下文字段与普通 `pull_event.node_id` 的用途不同，不能互换。实现见 [sproto 水位接口](../crates/sproto/WATERMARK_PROBE.md)。原始反汇编与服务器样本不公开。

实际顺序为：**取得 S0 → 查询当前选定根 → 枚举完整当前子树 → 收敛 S0 之后事件 → 验证并提交完整快照及最终事件位置**。S0 只是扫描起点，不写入 Store 的 received/committed cursor。列表字符串 cursor、单文件 sync/max 版本都不能替代事件位置。

扫描期间普通文件修改、移动和删除由[局部目录收敛](SNAPSHOT_CONVERGENCE.md)处理。事件仅使相关目录失效，重新列举当前状态；不拿旧事件元数据覆盖更新的列表。每次局部重查后继续 fence，只有静止空批覆盖全部重查后才返回完整候选。目录变化、权限歧义仍保留原有安全整树回退。

同次恢复重试从已捕获 S0 补拉根变化，再枚举和核对；不跨重连借用未经验证的种子。当前水位与根查询共享一个 900 秒绝对 deadline，取消/失败不会返回半种子。服务端恢复标识、所选范围、根身份、最终游标和既有 dirty 草稿保护均保持。

## 兼容边界

- 路径 `/` 尚无本轮验证的当前根元数据查询，保留历史 seed 路径；本轮不能宣称所有团队根都消除了历史读取。
- 分层权限可能允许访问选定子树而拒绝列父目录。只有父列表已知的 12290 权限拒绝可回到原有历史元数据获取；不能凭 S0 构造虚假根。身份不匹配、当前根缺失、传输错误或异常响应不降级成成功。
- 新 GUI 分开显示“取得当前事件水位并核对根目录”“读取目录历史”“枚举目录”“协调扫描期间变化的目录”和最终提交。FSD/worker IPC 为 15；schema18 不变。
- 本轮仍在完整候选确认后一次提交，**不提供逐目录提前可见或跨重启续扫**。这些能力需要[持久候选、覆盖状态与写回门禁](INITIALIZATION_INCREMENTAL_PLAN.md)，不能用单目录调用现有全量替换器。

## 验证口径

2026-11-01，在目标服务器 build17892 的选定个人子目录完成只读协议核验：当前水位约 17ms，根查询约 35ms，file/node/name/type/live 全部匹配；从 S0 Pull 返回静止空批，后续水位不倒退，无恢复标记。未进行 NAS 写操作。该单次观测证明这个范围的请求和事件位置可衔接，不代表所有范围、并发修改或完整初始化已经验收。

核心回归验证不同历史水位下起点获取仍只有水位和当前根两项逻辑操作（父目录列表仍需正常分页）、严格先 S0 后元数据、根替换及恢复标识拒绝、统一 deadline、S0 后根变化需重新归约并通过最终 fence。局部收敛另有模拟并发与真实本地 Store 草稿保持回归。完整整合、真实只读初始化、安装包与数据保留结果以发行包 `VALIDATION.json` 为准；不将目录列表完成时间写作 FUSE 首次可见时间。
