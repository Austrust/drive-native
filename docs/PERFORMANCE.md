# 多挂载性能与重连修复

验证日期：2026-10-30 至 2026-10-31。版本：`0.1.0~dev20261030.6`。环境：WSL Ubuntu 24.04、真实 Drive Server 4.0.3-27892、六个隔离只读任务。测试未修改 NAS 文件或权限。

## 问题与修改

1. 目录图标递归计算逐节点访问数据库并长期持有 Store 锁，使文件系统和状态接口一起阻塞。改为每批一次元数据读取、相关子树状态快照，并在共享锁外聚合；缓存、草稿、冲突及传输错误仍执行真实状态核对。
2. 下载调度先枚举全部未缓存文件，再逐项判断是否需要下载。改为 SQL 先筛选已有缓存、继承固定或有下载意图的文件，避免大型仅在线树的大量无效查询。
3. 历史删除事件只有删除标记、类型及版本，不包含完整活文件属性。仅对删除记录允许缺失这些属性；活文件必需字段仍严格验证。
4. 含无权子目录的根每次网络重连都会完整枚举。现在同一显式会话内按事件游标续接；重新登录、暂停后恢复、证书变更仍核对权限，游标或服务器恢复标识失效仍触发索引恢复。

## 常驻探针

使用 [watch_mounts.py](../scripts/watch_mounts.py)，通过本地 D-Bus 监听服务归属变化，每 10 秒记录状态、目录延迟和进程统计，每 6 次采样增加目录状态查询。它不扫描远端目录、不下载正文，不参与同步决策。日志 8 MiB 轮换，保留三个旧文件。

```sh
python3 scripts/watch_mounts.py --state-dir /path/to/isolated-test-state
```

目录中的 `catalog.json` 为测试任务清单，每项含 `instance`、`name`、`bus`、`mount`。结果写入同目录 `watch-probe.jsonl`。实际测试使用用户级常驻服务，原一分钟 systemd timer 与十五分钟线程自动任务已停用。

## 边界

这是开发测试包。worker 中断不等于物理网络的全部故障情形；完整 24 小时稳定性、Mint 实机桌面和休眠恢复尚未完成。命名空间并发写入的既有关卡保留，状态数据库 schema 18、IPC 12 不变。未在远端 Mint 设备安装本包。

## Windows 参考与设计边界

沿用项目 Windows 静态拆解所支持的占位元数据/正文分离、Fetch/Cancel 生命周期、后台缓存更新与同步/固定状态分离。未据此声称掌握官方图标汇总或重连重扫算法。当前仍按批遍历元数据，尚未实现逐事件增量更新祖先汇总。权限变更通知的完整语义未实测；对已隔离目录的重新授权，当前使用重新登录或暂停/恢复主动核对，不宣称仅靠事件游标即可覆盖全部 ACL 变化。

## 锁隔离并发复测（2026-10-31）

两个目录状态请求流加一个普通状态请求流，同时作用于大团队与个人大子树，共 48 次请求，全部成功。锁外聚合前后，个人 GetOverview 最长响应从 2.361 s 降至 0.931 s，团队从 0.904 s 降至 0.288 s。个人 GetStates 最长仍为 2.336 s：批量索引和汇总仍有遍历成本，不能宣称已实现增量图标算法。状态快照只核对本批相关子树的详细缓存/冲突信息，损坏缓存按路径返回错误，不扩大为整批失败。

锁外聚合最终包再次验证：团队约 2.10 MB PDF 首次 0.245 s / 再次 0.119 s，个人子树约 2.01 MB PDF 首次 0.289 s / 再次 0.180 s，内容一致。包内 fsd SHA-256 3082a758f32b7c0ecfda5058e2dc629b8d41172dacafdd798ca613c0aaf61678，worker 中断 2.067 s 恢复、无探测错误，缓存读取 19 ms 且内容一致。
