# Drive Native：本地性能诊断进展

当前仍为开发测试版本，尚未达到候选发布门槛。本轮没有更改产品运行行为或发布新安装包。

在WSL Ubuntu24.04的离线合成数据集上，测试了210,000个节点、2,000项子目录以及1MiB完整缓存文件。混合负载包含48路目录、状态查询及已打开文件读取。

诊断计时发现：

- 混合负载中，缓存读取回调的队列等待p95为4.856秒，任务执行p95为0.088毫秒。后续需要将完整缓存读取与重型元数据作业分开调度。
- 状态查询等待共享Store锁的p95为7.074秒。后续需要用增量状态聚合替代每批查询重新读取、构建整树。
- 独立枚举2,000项子目录时，每次完整枚举都会构建三遍包含点目录的2,002项列表，最后一遍仅返回EOF。后续需要稳定的目录句柄视图，并定义并发命名空间变化的可见性。

单独读取已打开的1MiB缓存文件，整文件读取p95约5.4毫秒；混合负载中升至约9.37秒，目录请求出现76/80次超时。所有失败保留，不能将测量完成等同于性能通过。

这些数值来自带计时标记的隔离诊断构建，内部计时含预热、按回调计数；不能与整文件请求百分位直接相加，也不用于宣称相对冻结版本的加速。运行库测试55项通过、1项忽略；没有将本轮结果声称为全产品或桌面验收。

原生同步方面也已定位两个问题：本地长轮询截止会提前结束合法等待；短间隔重复下载可能触发服务器拒绝，部分重试等待不能归为持续内容校验。这些结论尚未转化为已验证的产品修复。

另一次相同规模的混合负载后退出诊断正常完成，仍不足以关闭此前间歇性退出超时问题。完整长期基线尚待审查通过，后续产品修改须按相同工作量重新验证。

本页仅公开结论。此次新增的原始日志、内部环境信息、协议样本和服务器反汇编证据保留在本地，不随本次提交发布。当前阶段状态见[验收门槛](../DELIVERY_GATES.md)。

## 独立链路与观察窗口后续

用户随后授权安装iperf3。从ESnet官方3.21源码校验构建静态工具，上游5项测试通过；安装在NAS管理账号用户目录，未替换DSM系统组件。两方向各一次3秒预热、三次10秒正式单流TCP测量，正式阶段排除开始2秒。NAS→WSL接收吞吐中位数44.350MiB/s、最大46.950MiB/s；WSL→NAS中位数27.997MiB/s、最大28.088MiB/s。正式6次均成功；服务器单次连接后退出，结束确认无残留监听。

这是独立TCP网络对照，不包含原生协议、TLS、磁盘或校验开销；每方向仅3样本，p95/p99等于最大值，不代表长期尾部。旧应用吞吐来自不同时间和负载条件，不能直接相除作为80%达标证据。

首个24小时观察窗口实际在约11.62小时中断，保留25092个样本及43个失败样本，没有完成标记。随后确认测试用户未启用linger，用户服务管理器会随会话退出；已启用linger并增加有界WSL驻留。恢复只读任务并核验原二进制后，第二窗口于2026-10-31 13:00:41（Asia/Shanghai）独立开始；不与第一窗口拼接。该措施修复测试环境生命周期，不是已经修复客户端停止超时或通过24小时稳定性验收。

本次无产品运行代码变更、无新deb；安装记录、原始测量和中断现场继续保留本地。

## 持有句柄时停止挂载

离线三节点夹具对冻结版本做了两轮对照。无保留句柄时服务正常快速退出；文件和目录句柄各两次均在停止后的5秒观察结束时仍等待，释放句柄后约0.12秒正常退出。等待时存在FUSE内核读取线程。这复现了一个停止等待条件，但没有证明所有历史停止超时同源，也没有实施修复。

后续退出设计需要区分路径卸载和旧句柄排空，并验证写入持久性；不能用强杀掩盖等待。首次夹具因状态目录权限错误未挂载，修正后的独立六次对照才计入上述结论。详细记录保留本地；本次无产品运行代码变更、无新deb，P0仍待完整观察窗口。
