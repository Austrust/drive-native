# P0 MFM：483秒正常响应，停止阶段仍超时

2026-10-31，WSL Ubuntu24.04。隔离MFM实例在原生请求开始后 **483.633068秒**收到并解析正常响应，空changes、profile未变化；外层RPC在483.633883秒确认通知。这给出了服务器允许等待超过450秒的真实样本，补强[003的静态与失败证据](../p0-wait-deadline-003/REPORT.md)。但随后显式停止未正常完成：20.247877秒后systemd以SIGKILL结束主进程，退出状态9。**本轮不是整体修复通过。**

## 身份和方法

基于干净源码`b3e0706`，一次性构建仅增加阶段记录并将原生绝对截止设为600秒、外层RPC设为650秒；请求timeout仍为400。它没有实现官方的底层读取进展计时，也没有修改产品源码、安装包或六个冻结`.6`任务。

- fsd SHA-256：`1de5dae9db13aa7d938f548929617d70558c915cba3bac1cc7c7acb8648ed206`。
- worker SHA-256：`dd2da8b5f0f662141b967f1d13eae2e9c845e889a6f913b364f93446446850fc`。
- MFM只读副本91,033节点；权限排除项仍按现有流程处理，没有NAS写入或权限修改。
- 预先限定初始化300秒，在线后观察1100秒；首个超过450秒且被bridge确认的通知、终止错误或时间上限触发停止，不事后延长窗口。
- 132项协议单元测试、2项文档测试通过，1项文档测试忽略。没有全产品/GUI重跑，不能据此发布产品修复包。

## 停止失败的边界

[完整日志](final-trace.jsonl)显示：正常通知之后已发起下一次长轮询；观察器随后请求停止。`shutdown_begin/end`两次均完成，桥接等待以`io_NotConnected`结束，发生在显式停止之后，不能记为自发断连。到第5、10、15秒主进程仍为deactivating，线程聚合包括futex等待和一个`fuse_dev_do_read`；最后由systemd结束。

这些证据排除了“本次shutdown函数一直没返回”这一解释，但还不能确定是任务join、FUSE卸载、其他持锁工作或其组合。现有采样只收集主进程以及主线程`children`中可见的直接子进程，没有遍历每个线程的children；它不构成完整进程树证据，也不能用没有列出worker来证明worker已退出。下一次短测需要任务join/挂载join分段，并改进子进程枚举。

原六个FSD PID及`.6`哈希在导出时保持。24小时观察进度约3.79小时、第1364轮、16个失败采样；仍未满24小时。长期基线没有替换二进制。

## 结论与下一步

450秒截止确实会截断服务器合法等待；600/650秒诊断预算接收到了一个483秒正常样本。仍需独立设计原生进展超时、外层等待与取消契约，不能把这两个数字直接当完整修复。正常停止缺陷继续开放，结合[002](../p0-wait-deadline-002/REPORT.md)与固定高负载停止失败继续定位。
