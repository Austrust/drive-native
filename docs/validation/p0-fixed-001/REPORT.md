# P0：固定本地夹具定位性能干扰

固定 `.6` 二进制在完全离线的合成树中，单独缓存读取较快，但目录与状态查询会拖慢并发缓存读取。即使提前打开句柄，混合读取 p95 仍为 9.118 秒。因此不能将该现象归因于 NAS 响应，P1 必须处理本地调度/锁范围。运行时未作性能修改。

## 条件与重现

- 精确 210,000 节点，106 目录（含根）、209,894 文件；指定目录 2,000 子项，缓存 1,048,576 字节。[确定性数据清单](fixture.json)包含数据集及内容 SHA-256。
- 创建器：[performance_fixture.rs](../../../crates/drive-core/examples/performance_fixture.rs)，创建器源码提交 `a2e65b0`，通过既有 Store 接口生成；不复制真实账号目录。
- fsd 来自 `.6` 安装包，SHA-256 `3082a758f32b7c0ecfda5058e2dc629b8d41172dacafdd798ca613c0aaf61678`，源码 `62be13c9f9f4a2457a3040829f478bf43b1821df`；环境同[身份核验](../p0-baseline-audit.json)。[context.json](context.json)记录初次夹具目录权限错误及仅对失败合成服务的修正重启，未中断六个真实基线挂载。
- 服务保持 locked，无账号凭据、无网络 worker；合成配置地址为 loopback discard。其他六任务及探针继续运行，是已知外部干扰。
- [测试程序](../../../scripts/validation/benchmark_local.py)：操作计时在 worker 启动/准备完成后开始，启动延迟和父进程墙钟时间另列。状态查询用 Gio 持有 D-Bus 连接；所有超时及失败保留，nearest-rank 统计。成功耗时包含校验与关闭；held_read 打开在计时之前。
- 分项各 2 次预热、30 次测量；混合各 3 类×16 路，5轮，共240请求，每类另预热2次。48客户端用屏障同时开始。超时15秒的值为右删失下界，不是完成延迟。
- 页缓存分组针对 backing blob：warm 测得 256/256 页驻留；disk 使用文件级 DONTNEED 后测得0/256页驻留，各30/30样本满足条件。FUSE open 使用 DIRECT_IO；未清理主机/虚拟磁盘/硬件缓存，不将 disk 组叫作物理冷盘。

## 结论与边界

共享本地队列中的缓存读即使不需要网络、也无需重新打开句柄，仍受混合负载影响。结合[真实树失败基线中的源码调用链](../p0-mixed-48-001/REPORT.md)，下一步应分离状态捕获、目录枚举和缓存读的锁/调度；不能只增加网络重试或将错误归类为连接中断。

尚未直接记录锁持有时间，不能根据此表分配每个函数的延迟占比。更短的合成身份/名称、无ACL变更、无远端事件与真实工作负载不同。任何 P1 对比必须复用本夹具、程序与预注册条件；不能用本表与此前不同目录/含子进程启动计时直接计算加速倍数。

## 压测后空闲资源

另开90秒稳定期＋300.010秒窗口，[61个原始样本及统计](idle/summary.json)全部成功，PID集合稳定，实际可执行文件仍匹配 `.6`。按进程CPU累计秒/单调时间统计，单核CPU为0.100%；RSS全程1,773,828 KiB（约1.692 GiB），PSS约1,767,146 KiB；FD固定18、线程44。无GUI、无网络worker，只统计该离线任务。

该限定窗口CPU满足1%目标，但内存明显不满足300MB目标。不能把300秒零增长解释为7天稳定或无泄漏；也不能仅凭RSS断定泄漏，分配器保留/并发树副本等原因尚需定位。P1必须以同样并发后窗口比较内存，而非只测冷启动RSS。在线worker资源仍需单列。

普通重连、未缓存网络读取、故障持久性和24小时完整观察仍未完成。

## 生命周期失败现场

完成资源窗口后，显式停止该固定夹具服务：01:22:30 收到停止请求，01:24:01 systemd 因停止超时发送 SIGKILL。`Result=timeout`、`ExecMainStatus=9`，见 [stop-result.json](stop-result.json) 及 [原始服务日志](stop-journal.txt)。这是一次失败，不能因 `systemctl stop` 命令退出0就记为正常退出。真实六挂载未被停止。

停止过程中，多线程等待 futex，一个线程等待 FUSE 设备读取。尝试抓取 gdb 栈前进程已被 systemd 终止，未得到栈，根因待复现。P1 需要核查超时请求、队列、挂载卸载与 join 的退出顺序，不能先断定与内存或网络有关。

通用启动工具另建的新夹具实际通过挂载、目录和内容校验并正常停止，[检查记录](launcher-check.json)同时保留上述长测实例的超时结果。两个合成状态目录及原始样本均保留，结束后不再占用进程内存。该短测中的只读目录 fsync 返回0，但实现未覆盖 fsyncdir，不能把系统调用成功推论为可写目录持久性已完成。
