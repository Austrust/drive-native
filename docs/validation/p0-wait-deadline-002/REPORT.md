# P0 MFM阶段诊断：初始化门槛未通过，停止超时

2026-10-31，WSL Ubuntu 24.04。为补查[上一轮未复现](../p0-wait-deadline-001/REPORT.md)，从MFM协作91,033节点元数据建立新只读实例，增加发送完成、接收完整帧、keep_alive及通知数量日志。此次没有进入预设900秒长轮询观察：初始化在线门槛未通过，随后停止操作超过systemd的20秒上限，进程被SIGKILL。必须保留为初始化/退出失败，不能记为长轮询复现或测试通过。

## 实际经过与证据边界

- 一次性诊断构建来自干净提交 `87320885899d7ad8daebc568fbfe76ee3e4bca84`，两级截止为外层470秒、原生450秒。完整二进制SHA-256见[manifest](manifest.json)；不属于安装包或产品修复。
- 账号解锁请求已接受，但观察器没有记录成功的online＋mounted条件。`observed_rows=0`，最终过滤后的阶段日志也为空，因此不能说已运行900秒长轮询。
- 工具初始化检查把“needs_attention”与“45秒内未在线”都折叠为`RuntimeError`，没有保存最后一次状态；现存记录无法区分这两个分支。不能把泛化异常准确归因为认证失败、网络超时或单纯45秒截止。下一版工具需分别保存错误类别、每次状态及单调时钟耗时。
- 显式停止耗时20.204600秒；systemd Result=timeout、ExecMainStatus=9、MainPID=0，挂载已消失。日志分类确认发生stop-sigterm超时，而非systemd启动超时。控制器正常结束不等于被测服务正常退出。
- 只读检查遗留数据库：91,033节点、12条access_denied、非空已提交游标、0待提交操作、0脏草稿。没有导出文件名、正文、游标值或配置凭据。

源码`Bridge::initial_pull`在access_denied非零时调用`rebuild_snapshot`，后者有单独的快照请求、数据库安装和失效通知阶段。这解释了为什么“大目录副本”不能按小目录的45秒初始化预算直接进入长轮询，但本次没有阶段日志，不能证明具体卡在哪一阶段。保持权限核对语义；不清空access_denied、不跳过快照来制造通过。停止超时也不能仅凭相同现象归为此前固定夹具的同一根因。
