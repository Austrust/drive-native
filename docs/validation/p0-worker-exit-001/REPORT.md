# P0 内核退出事件：450秒周期复核

对六个已经运行的 `.6` worker 分别注册一次Linux pidfd退出通知。只观察现有进程，不附加调试器、不读取内存、不发信号、不请求NAS。每个任务最多等待600秒；六个任务均收到退出事件，探针已正常结束。

| 任务 | 观测生命周期，秒 | 退出时原FUSE主PID仍存在 |
|---|---:|---|
| MFM协作 | 450.25 | 是 |
| 培养 | 450.23 | 是 |
| 实验报销 | 450.23 | 是 |
| 模拟报销 | 450.29 | 是 |
| 我的文件 | 1251.04 | 是 |
| Personal_Sync | 1251.04 | 是 |

生命周期由`/proc/<pid>/stat`的启动tick和pidfd就绪时的CLOCK_BOOTTIME相减。HZ=100，且含通知调度延迟，因此不声称毫秒级精确退出时刻。六个worker哈希均为冻结 `.6`，没有把新构建或其他程序混入统计。

四个团队目录的退出时刻非常接近源码中的450秒Wait截止，与[10秒采样的78个区间分析](../p0-observation-review-001/REPORT.md)一致。两个个人目录的较长生命周期也保留，不能推广成“所有worker每450秒必定退出”。本次没有记录各次Wait起止及返回原因，也没有冻结真实远端目录；更长区间不能用于反推其间没有事件。

pidfd不是父进程wait接口，本工具没有退出码或信号来源，故尚不能区分外层RPC截止、原生请求截止、服务器关闭、其他本地错误。FUSE进程存在也不等于该时刻目录或正文可读。下一步在隔离诊断构建中记录请求阶段、耗时和错误类别，对照官方长轮询的空闲回复及连接恢复语义；不记录凭据、原始响应或文件正文，不改变冻结基线。
