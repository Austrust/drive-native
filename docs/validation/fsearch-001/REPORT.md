# 原版 FSearch 扫描与功能复放

2026-11-03：未修改的 FSearch 0.3.1 在相同 WSL 环境、相同合成树上完成18次配对扫描。相对自建 `.7`，新版首扫中位数从170.161秒降至78.773秒，重复扫描从162.435秒降至70.052秒。独立本地目录约0.465秒，剩余差距仍大；**issue #5 保持开放**，这些结果不等于达到接近本地或官方客户端的体验。

机器可读统计、三轮原始秒数、源码与二进制哈希见 [SUMMARY.json](SUMMARY.json)。复放命令与独立索引审计器见 [工具说明](../../../scripts/validation/FSEARCH.md)。这里仅公开聚合；运行数据库、完整日志和原始索引TSV留在本地证据中。

相对自建基线耗时分别减少53.7%和56.9%，基线/新版中位数比为2.160和2.319。**这些比值不是与官方客户端的对照**。baseline、fixed、local各三轮first/repeat，顺序交替；每轮新建夹具，repeat复用同一挂载与配置。first没有清空宿主页面缓存。

每个夹具含100,064文件和2,066目录。18次均从原版FSearch保存的真实索引核对102,130项，路径、类型、大小、mtime无缺失、额外、重复或差异；正文hydration为0。CLI返回码之外，还检查保存失败警告和数据库新保存证据。每个夹具均正常停止。

基线源码是 `036dbeaa98377fe32d26cba681c0254d6cdd8312`，修复源码是 `a9b424733c2962b950e638fd804837a3a2e447c2`。它的 `drive-core/src`、`drive-fs/src`、`sproto/src` 与终包冻结 `416cc41b11fce2774bc8eb1e899e100f3d896b8f` 经Git逐字比较无差异。两版复制同一个合成夹具代码；原版FSearch和审计器二进制保持相同。完整哈希列在SUMMARY。

窗口内未调度WSL编译、NAS测试或其他扫描，但仍有少量Windows代码/文档读写与Git提交/检查。它不是整机严格空载实验。独立本地目录只作为参照，没有向FUSE扫描提供镜像目录；未做同机官方按需客户端对照。

## 独立功能复放

使用终包冻结416cc41b另编译显式可写合成夹具；与包编译重叠，耗时不进入上面的性能比较。

- 原版FSearch实际产生3次opendir后，对它的私有进程组发送SIGTERM；退出码为-15。随后挂载仍可浏览，重新启动原版扫描，11,630项全部匹配。
- 通过真实挂载完成rename、delete、create、写入、fsync和文件utime，再由原版FSearch完整重扫11,630项，真值仍全部匹配，未上传草稿内容可读。
- 扫描期间另一个独立小挂载14次查询均成功；最大13.67毫秒仅是共享负载下的功能观察。
- 两次完整扫描分别观察到566次opendir和566次releasedir；总hydration为0。两挂载均正常退出、无残留挂载。

诊断运行显示首次扫描的目录提交累计约2.110秒，编辑后重扫约0.0035秒；LOOKUP/GETATTR投影每类仍各累计约2.3–2.5秒。阶段计时可能嵌套，且该运行有竞争构建，不能相加成独立性能归因。后续优化应继续检查逐项属性请求与批量投影，而不是把这一轮改善说成问题完全解决。

首次fixture构建暴露默认features缺少OptionalExtension导入，修复后新run构建成功；旧记录保留。functional001的工具哈希循环误读__pycache__目录，在启动夹具前失败；修正后另建functional002通过。这两次失败没有抹掉，也不计为成功测试。

## 仍未覆盖的验收

SIGTERM测试不是GUI取消按钮。实际FSearch下的ACL撤销、冷启动预览切换、远端事件后索引刷新和自动monitor行为仍未实测；配对扫描关闭了FSearch monitor。同机官方客户端基准也未执行。
