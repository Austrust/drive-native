# FUSE 稳定目录视图

2026-10-31。在已发布 `.3` 的完整内容读取隔离上，继续修复目录续读。当前为隔离开发源码；不将它记作 P1 性能验收通过，也不改变原 P0 实例。

## 行为与实现

`opendir` 通过 [轻量投影](../crates/drive-core/src/filesystem.rs) 一次取得可见条目的 inode、名称和类型。首次 inode 分配使用同一个 SQLite 事务的批量插入；已存在的 inode 不重分配。保留权限过滤、删除标记、名称排序和本地创建遮蔽规则，不查询正文、草稿属性或逐文件同步状态。

[目录句柄](../crates/drive-fs/src/directory.rs) 持有不可变视图。后续 `readdir`、EOF、seek 和 rewind 使用同一列表及位置 cookie，不再取得 Store 锁或重建整目录。改名、新增和删除发生后，新打开的目录取得新视图；旧句柄保持原有顺序。列表中保留旧名称不绕过后续 lookup/open 的身份与权限检查。

同目录且本地 revision 相同的同时打开句柄可共享视图；revision 暂用保守的 SQLite `total_changes`，因此非命名空间写入也可能使新打开重新投影。这是正确性优先的过渡实现，不能称为精确目录版本或增量状态索引。

视图按条目及字符串容量计账，上限 64 MiB；同时目录句柄上限 4096。超限返回明确错误，不返回空目录。旧视图仍有在途读取时保持占用，最后一个引用释放才扣减。句柄表和弱引用索引另有有界开销，64 MiB 不是整个进程 RSS 上限。目录关闭直接移除本地句柄，最后一个引用将视图交给独立回收线程，实际释放后才归还额度。独立视图（含构建预留、在用与待回收）同样最多4096份，回收通道预留相同容量，不会因普通工作队列拒绝任务而丢失关闭请求；回收线程异常时保留同步释放的兜底路径。

## 验证与范围

- 核心测试覆盖 2000 子项、首次及重复 inode 分配、内存预算拒绝、本地创建遮蔽、权限过滤和正文文件丢失时仍能枚举目录。
- 目录表测试覆盖共享视图、变更后的新视图、无效句柄、读取引用保护以及句柄/内存上限。
- [真实内核测试](../crates/drive-fs/tests/directory_views.rs) 用 512 字节 `getdents64` 缓冲强制续读，在远端索引改名/删除/新增后持住 Store 锁，检查旧/新目录、EOF、cookie 回退与 rewind。

独立快照 `directory-views-005` 已通过394项工作区 Rust 回归（默认11项跳过），随后显式运行10项 FUSE 内核回归全部通过；剩余1项为文档示例跳过。回收器排队上限及晚于句柄表的读取引用回归包含在其中。固定样本同条件性能比较仍待完成。此回归证明续读不等待 Store，不能证明首次打开、Nemo 整体加载或 48 路混合负载达标。

新 `opendir` 仍需取得 Store；全树状态聚合仍需进一步重构。队列等待插桩、写入字节预算、增量目录状态、全部初始化/退出及普通目录全量同步均不由这项改动完成。发布条件与验收状态见 [P1 契约](P1_ARCHITECTURE.md)和[唯一验收表](../DELIVERY_GATES.md)。
