# 枚举失败的竞态重试分类

2026-10-31。基于 `92c7ceb` 的独立最小修复；来源为本项目快照代码静态审查，不引入第三方代码。它修正一个可用合成样本复现的重试条件，尚未证明是 Personal 长初始化的实网根因，也不包含在此前 `.4` 构建中。

## 问题与修改

原实现遇到任何目录枚举错误都会额外 Pull；只要全局 cursor 推进且未标记 recovery_required，就把错误改成 SnapshotChanged。即使 scoped events 为空也会重做整份候选。因此权限拒绝、格式/容量错误或传输故障可能被无关服务器活动误分类为枚举竞态。

[快照实现](../crates/drive-core/src/native_snapshot.rs)现在仅在本地确实发现重复文件身份或同名条目时保留一份私有冲突证据，最多两个文件身份。只有事件流向前推进、没有恢复标记，且事件涉及这些身份并位于选定范围（包括移入/移出）时才允许 SnapshotChanged 重试。

空推进页不是竞态证据，也不是事件边界；相关事件可能位于后续页。仅对上述真实碰撞继续有界核对，到相关事件、静止/倒退边界、恢复标记或预算终止。核对采用现有围栏的 4096 页/900 秒循环预算，当前原生请求仍使用已有期限；没有证据或预算未能完成时保留原碰撞错误，不猜测安全重试。核对本身的网络/根身份错误保留其类型。

其他枚举错误直接保留原类别，不额外请求事件。没有通过匹配错误文字来创建冲突证据；正常子目录 12290 权限跳过逻辑保持不变。最终一致性 fence、每次恢复最多三轮、seed 起点和快照导入全部保持原语义。

## 明确边界

- 相关身份事件是允许重新枚举的证据，不授权安装失败候选；后续新候选仍必须通过原 fence。
- 当前事件模型的 Modify 同时承载常规更新，不能据字段名进一步猜测所有 namespace 操作；只用身份和范围相关性作保守重试门槛。
- 如果目录路径变化只返回服务端错误，或事件只包含祖先、不包含碰撞身份，目前没有足够协议保证安全归为竞态。这些错误保留原类别；不能恢复“任意错误+任意全局推进即可重试”的行为。
- 本批不处理持续写入导致 fence 一直拒绝候选、不复用 seed 检查点、不修改权限 generation，也不宣称整个 Personal 恢复问题完成。
