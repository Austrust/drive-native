# Drive Native .20261113.2：13 项性能热点收尾（#87–#94 与 #23/#26/#30/#57/#59 补充）

开发版 `0.1.0~dev20261113.2`，面向 Ubuntu 24.04／Mint 的后续试用。本版把 2026-11-13 性能复核提出的 **13 项问题**全部合入 `main`（draft PR #95–#101）：新增 issue #87–#94，以及 #26/#23/#30/#59/#57 的补充验收项。数据库 schema 保持 **29**、IPC 保持 **21**（本版无迁移，JSON/DB 变更均为 additive）。FSD 与 worker 必须成对更新。

## 本次改善

- **#87 排除清理去重（P1）**：大批量排除清理原先在 Store 写事务内用 `Vec::contains` 合并已清理 id，K 个唯一 id 需要 K(K−1)/2 次字符串比较且锁内完成。现改为一次构建 HashSet 的 O(K+P) membership，旧列表解析/建集合移到写事务外，事务内重读 raw metadata 做防御性快照校验；序列化顺序与重复语义、排除规则语义、冲突/未上传正文保护、规则移除恢复均不变，绝不发送远端删除。
- **#91 abandoned 五态 partial index（P2）**：缓存候选保护集合包含 `pending/inflight/uncertain/conflict/abandoned` 五态，而活跃 partial index 只有四态，导致候选查询退化为全历史扫描。现统一为五态；对**已处于 schema 29 的旧库**在 open 迁移事务内检查 `sqlite_master.sql` 并显式 DROP+CREATE（幂等、失败回滚、数据无损），`CREATE INDEX IF NOT EXISTS` 不会漏掉旧同名索引。
- **#88 GetOverview 提交诊断（P2）**：此前每次 overview 都执行两个 count + `list(20)`，扫描包含成功 confirmed 历史的 `commit_diagnostics` 视图并排序。现在 `commit_diagnostics::snapshot()` 在一次一致读事务内返回两个计数与 top-20（两个 count 合并为一条语句，list 改为可证明等价的 per-journal 每类 top-k 合并），并新增 outcome 相关 partial index；桌面侧以 `(CommitState, PRAGMA data_version)` 为 key 缓存，`consistent=false` 时不发布缓存，writer fallback 不缓存。
- **#89 GetOverview storage 摘要（P2）**：此前每次请求都 read_dir 草稿目录、逐文件 stat 并解析全部 quarantine 记录。现在 storage 摘要带跨句柄共享 generation + 2s 有界 TTL + `PRAGMA data_version` 双键缓存，仅轮外发布；扫描失败返回上次好快照并标 `stale/error`（additive 字段），不会把错误统计成 0；`GetCacheSettings` 仍走精确扫描。
- **#90 缓存 GC 锁区与 clean draft 提交（P1）**：`maintain_cache` 不再在 flights+Store 锁内做全量 blobs/drafts 遍历、重复 usage 扫描与删除；改为有界、可取消、可跨调用恢复的窗口（128 候选/窗口），锁外 inventory、锁内重验 keep-set/打开句柄/活动下载/候选身份后再删除；clean draft 元数据改为有界批事务（128 行/批，`ceil(C/128)` 次提交），提交后才 unlink 文件；淘汰只发生在**完整轮**的 Usage 阶段（恢复 legacy「先 GC 后释放」顺序），released inode 的 `Invalidation::Inode` 通知在普通与跨轮恢复路径都恰好一次。WAL 与 `synchronous=FULL` 未改动。
- **#92 多挂载传输轮询（P2）**：周期 tick 与单 slot 查询拆开，每 slot 最小间隔 1.0s、至多 1 in-flight + 1 合并补刷，回包只安排自身补刷；其余挂载不再被连带触发。`(sequence,bus,task,owner generation)` 校验旧回包，替换/删除 slot 清理状态；保留最后有效状态、错误提示与托盘更新。
- **#93 「加载更多」分页（P2）**：后端 `GetDirectory` 响应新增 additive `listing_cookie`（取已提交命名空间语义版本，ACL/草稿/成员变化都会使其变化；旧客户端忽略该字段），GUI 在同一目录快照内按 cookie 追加下一页，cookie 缺失/变化、owner/task/视图代际变化或旧乱序回包时保守全量重读；preview 撤权清空逻辑保持不变。2560 项目录十屏从 55 次/14,080 项降为 10 次/2,560 项。
- **#23 热索引 opendir（P1 补充）**：`DirBlock` 构建时一次预计算 `estimated_bytes`（结构体+Vec capacity+名字字节，saturating），索引命中 opendir 在锁内只读字段，不再每次遍历全部 entry 名字；共享 Arc 的每 View 保守计费、MAX_BYTES/MAX_HANDLES 与回收器语义不变。
- **#26 ACL READDIRPLUS（P1 补充）**：`send_acl_plus` 先取长度并判断 offset/EOF，只对当前 `[index..end]` 构造 ≤128 项 slots（借用页接口统一 indexed/snapshot 两种 origin），不再每次 continuation 在 Store/publication guard 内全量 collect 整个目录；权限校验、preview stamp、EAGAIN、允许/denied 发布与 cookie 语义不变。
- **#30 warm 投影后的目录聚合（P2 补充）**：状态投影每代携带失效集（变更行/父边/继承链根），桌面已提交 render 按失效集增量刷新，只重算变更行与祖先链；同代 single-flight，generation 跳代/重建/未追平/超阈值/detail 缺口时回退现有全量 render 或权威路径。294k 合成树同代重复 root 查询 100/100 命中、0 次全量 render/tree walk，单叶提交只重算 3 个节点，与权威渲染逐字段一致。
- **#57 命名空间扫描窗口（P0 补充）**：扫描改为有界分页 + 跨轮可恢复游标 + prefix digest 缓存；候选对游标前**全部**更早 intent 的 writes/reads/paths 压缩屏障做等价 pairwise 依赖判断（不 OFFSET 跳过），硬屏障给出诊断与恢复出口。窗口外后缀不再永久饿死（255/256/257 首轮、1024 第 3 轮获得 attempt）；reconcile attempt 增加有界执行预算（默认 15s）与 Timeout 诊断（operation 保持 uncertain + durable retry，不重放未确定远端写）；持续 pending 下 reconcile 有 10s aging 公平份额。
- **#59 FUSE 端到端期限（P1 补充）**：read 请求新增 single-claim 回复状态机与每挂载 deadline watchdog（worker/watchdog/interrupt 竞争唯一 reply，晚到结果丢弃、无双 reply）；过期排队任务不执行昂贵 hydration；`ReadCancellation` 增加 expiry-aware 接口，runtime 在入口/提交前/worker 入口检查并在不可抢占 hydration 上做有界并发（默认 8，RAII 回收、无孤儿）；新增分离的 queue/store/worker/reply 阶段延迟与 additive `fuse.request_deadline` 指标。offline cache hit、ACL 立即撤销、写路径未知结果不盲重试等契约不变；不通过调 `max_background` 冒充隔离。
- **#94 性能门禁（P2）**：`status_latency_210k` 改为显式模式（cold/startup、service+warm、forced-degraded、steady mixed），warm 必须证明投影 ready 且命中，未就绪 → INCONCLUSIVE 且非零退出；输出逐接口 p50/p95/p99/max/errors/timeouts/吞吐，classic 场景成为独立门禁（不再被混合聚合掩盖）；新增 `#94 VERDICT` 机读 verdict、注入自测、分阶段内存与缺失工作负载钩子；cold/degraded 只披露不当稳态通过。

## 行为变化与兼容

- **schema 仍为 29、IPC 仍为 21**：本版无迁移；新增/变更字段均为 additive（`GetDirectory` 的 `listing_cookie`、`GetOverview.fuse.request_deadline`、storage summary 的 `collected_at/stale/error`、命名空间调度诊断字段）。旧 GUI 忽略新字段；新 GUI 遇旧后端缺字段时保守全量刷新。
- **#59**：read 请求超预算时按既有语义回复 EIO，晚到 worker 结果被丢弃（不再作为第二次 reply）；该路径此前可能长时间等待阻塞 worker。写路径未知结果语义不变。
- **#90**：GC 改为分批窗口执行，取消/停止在窗口边界生效；clean draft 删除改为批事务，单次提交行数有界。
- **#93**：GUI 追加分页依赖后端 `listing_cookie`；升级必须 FSD/worker/GUI 成对更新。
- **#57**：命名空间派发在窗口外后缀可被扫描到；reconcile 超时产生显式 Timeout 诊断并保留 uncertain，不再静默无限等待。
- 排除规则默认值、缓存缺省行为等上一版行为变化保持不变；FSD 与 worker 仍须成对更新。

- 保存并关闭挂载内正在编辑的文件，暂停后安装；升级后 FSD/worker/GUI 成对切换。schema 不迁移、IPC 不升版，升级不需要额外 schema 备份步骤。
