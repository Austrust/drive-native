# Drive Native .20261108.1：上传终态、数据库热点与统一桌面

开发版 `0.1.0~dev20261108.1`，面向 Ubuntu 24.04／Mint 的后续试用。发布源提交为 `f6f48ea06ceefafd1e35e938ef4580c30994dcf0`（基于已合入 main 的验证树 `8646766`），数据库 schema28、IPC21（`.1` 发布源为 schema27，2026-11-09 最终合并树随 #32 升至 v28；本页功能与数字口径仍按 `.1` 树，最终树数字以 **TBD-FINAL** 标注）。该发布树含 #2（`3dd03a1`），但不含 #21–#30 的后续性能修复；本页 48 路 mixed 与计数均为 `.1` 树口径，最终合并树数字在相应位置以 **TBD-FINAL** 标注。本版把 #14/#17 未确认上传终态、#15/#16 本地 SQLite 热点、#8 已提交状态投影、#2 统一桌面与 #5 NamespaceIndex 精简投影合入主线后再构建。

## 本次改善

- **未确认上传终态（#14/#17）**：只读核对最多五次（10/30/120/300 秒退避），预算耗尽后操作进入可解释状态而不再无限重试；本地删除会作废对应的未确认创建；权限失败不再写成粘性背景错误。背景错误改为结构化字段（来源／种类／起始时间），上传成功或恢复后自动清除，瞬时失败与需处理失败分开呈现。
- **SQLite 热点与去全局锁读（#15/#16）**：schema27 为 operations 与 namespace_ops 增加节点索引，并为冲突、固定和缓存候选增加 nodes 部分索引；`sync_issues` 改为四支 UNION；问题与下载候选查询使用 keyset 分页；缓存候选集合化查询；`GetIssues` 不再在全局 Store 锁内执行。
- **已提交状态投影（#8）**：`GetStates` 改由已提交状态投影的只读 WAL 快照提供，并按提交日志增量维护、以 250 ms 节流发布；桌面读请求不再等待全局锁。210k 合成树的状态查询 p95 从约 470 ms 降到约 313 ms。
- **统一桌面（#2）**：所有挂载进入同一个管理窗口，保留托盘活动、持久同步历史和通知通道；后台接管的 schema 期望同步到 v27，修复了合并线中“应用后台更新”必然版本不匹配的问题。
- **NamespaceIndex 精简投影（#5）**：为 NamespaceIndex 构建成本设置上限，超预算时降级到精简投影而非全量扫描；配对元数据基准随源码归档提供。

## 实测结果

在 workstation202611（32 核／125 GiB，Ubuntu 24.04，内核 6.8.0-147）上，对与发布源代码相同的合并线（`.1` 树 `f6f48ea`；含 #2、不含 #21–#30 后续修复）做专项实测：

| 项目 | 结果 | 口径 |
|---|---:|---|
| 210k 合成树 GetStates p95 | 312.9 ms | SLO 500 ms；三树对比基线约 468.8 ms（fix-7/#8 分支线，未含 #2） |
| 2000 项目录列举 | 4.07 ms（Store）／0.727 ms（FUSE） | SLO 300 ms |
| 持有 Store 锁 2 秒时 GetStates／GetIssues | 310／314 ms | 旧线约 2352 ms |
| 48 路 mixed 负载超时 | 28 | SLO 0，**未达标**（`.1` 树；见下文原因） |
| 原版 FSearch 0.3.1 元数据扫描，369,298 项首扫／复扫 | 5.47／5.12 秒 | 对照 `.9` 的 17.48／17.10 秒，约缩短 69%／70% |
| 319,679 项密集树首扫／复扫 | 2.87／2.52 秒 | 对照 `.9` 的 8.78／8.37 秒 |
| 2000 项目录 FSearch 列举 | 约 0.465 秒 | 合成本地树 |

48 路 mixed 未达标的直接原因是（`.1` 树）`GetOverview` 仍在全局锁内计算问题计数与缓存可用性；#21 已将 GetOverview 迁移到只读连接（`desktop.rs overview_measured`，只读打开失败才回退 writer 锁），最终合并树的 48 路 mixed 结果：**TBD-FINAL**（待最终测量回填）。状态主路径已达标，但本版不宣称 #8 全量完成。FSearch 数据来自本地合成树，没有真实 NAS、宿主页缓存清空或官方客户端同机对照，不能当作真实 Personal_Sync 的端到端结果。

## 验证和升级

发布包由 `dpkg-buildpackage -b -us -uc -j4` 在干净 `git archive` 树上构建（`.1` 树 `f6f48ea`，测试未关闭）：workspace all-features 1097 通过／0 失败／52 忽略（60 个套件），default 1087／0／47；GUI 24 套／257 项通过；`scripts/verify.sh` 退出码 0，lab `--simulate` 报告 `passed=true`、`LocalComplete`。最终合并树（`integration/fixes2`）的全量计数：**TBD-FINAL**（待最终重跑回填）。包内容核对通过：三个 native 二进制、GUI onedir、`/usr/bin/drive-native` 包装、4 个 systemd user units、Nemo／Nautilus 扩展与 gio probe 齐备；`SOURCE_COMMIT` 与 `BUILD_VERSION` 与源一致，包内没有 docs/validation 证据、.git 或密钥材料。

schema 由 24→25→26→27→28 累积演进（24 同步历史，25 用户读写策略与逐动作权限，26 未确认上传核对预算，27 问题与下载候选索引，28 = #32 的 7 个 partial 索引（operations 计数/节点/内容/核对候选与 inbox 待处理共 5 个，sync_history 触发/结果游标 2 个）+ retention 历史裁剪 + 批量点查/上游祖先查询批量化；27→28 为唯一迁移路径）。FSD 与 worker 必须成对更新，旧程序不能读取新 schema。升级时先在任务界面选择“应用后台更新…”，按提示保存并关闭正在编辑的文件；升级会暂停并正常切换后台，保留任务、未上传修改和同步历史。不要通过清缓存处理升级或同步错误。

本构建机没有可用的 chroot/debootstrap，因此没有执行真实 dpkg 安装／升级／卸载验证；本版对安装流程的结论止于包内容与元数据层，真实 Mint／Cinnamon 桌面验收也未执行。
