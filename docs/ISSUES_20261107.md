# 本地 DB 热点、桌面读锁与增量状态投影

本页记录 issue [15](https://github.com/Austrust/drive-native/issues/15)、[16](https://github.com/Austrust/drive-native/issues/16)、[8](https://github.com/Austrust/drive-native/issues/8) 的修复与验证入口。基线为 `367e33d`（`.9` 冻结线），`.1` 候选合并树为 schema v27；2026-11-09 最终合并树（`integration/fixes2`）升为 schema v28（#32）。**2026-11-08 已合入 main（`8646766`），候选发布版 `0.1.0~dev20261108.1`**；#15/#16 已由作者关闭，#2/#5/#8/#14/#17 保持 open 并已在 issue 下补验证评论。发布口径仍以 [DELIVERY_GATES.md](../DELIVERY_GATES.md) 与安装包报告为准。本页性能数字的测量树在相应表格与条目内标注。

## 问题形状

约 29.4 万节点、`state.sqlite` 150 MB 量级的任务下，一次本地变更会触发数百 MB 的本地 DB 页读；四个查询热点与一把全局 Store 锁叠加：

- `desktop_status_seeds` 全表扫描 `nodes` 并逐行反连接：959 ms / 1.33 GiB / 294,023 行（只读连接实测）。
- `sync_issues` 对每个节点 `EXISTS operations(node)` / `namespace_ops(node)`，而两表只有 `id`/`seq` 的部分索引：约 9.5 亿次行访问；无问题也要 27.7 s / 1.04 GB。
- `cache_candidates` 每个候选都对 `nodes` 全表做 blob 共享/保护判定：12.26 s / 14.54 GiB / 300 行。
- `downloads_needed` 全表扫描 + `pinned_nodes` 递归，且上传循环每个 cycle 末尾无条件调用（约 120–195 ms/次、70–100 MB）。

这些查询与桌面接口共用全局 `SharedStore` 锁：GetIssues 卡 90 s 时 GetStates 12 s 超时（DBus NoReply）。issue #8 进一步要求目录浏览、状态查询、初始化从同一把锁解耦，并给出 210k 节点 p95 门槛。

## 修复

### 1. schema v27→v28 与只读句柄

`crates/drive-core/src/state.rs`：`STATE_SCHEMA_VERSION` 26→27，新增 5 个索引：

- `operations_node(operations.node)`、`namespace_ops_node(namespace_ops.node)`（普通索引）；
- `nodes_conflict(id) WHERE conflict=1`、`nodes_pinned(id) WHERE pinned=1`（partial）；
- `nodes_cached(id, local_version, remote_version) WHERE blob IS NOT NULL`（partial 覆盖索引，stale 候选无需回表）。

升级沿用既有 `BEGIN IMMEDIATE` + `VACUUM INTO state-before-v<目标版本>-<uuid>.sqlite` 备份；首次打开会阻塞 writer 完成备份+建索引。`.1` 树 v26→v27 在 294k release 实测 0.33–8.1 s（中位 5.22 s，盘上临时多约 143 MB）；最终树 v27→v28 仅新增 partial 索引，#32 微基准在 294k 合成库上为 769 ms（debug），release 数字 **TBD-FINAL**。

`Store::open_read_only(root)`：独立只读 SQLite 连接（`SQLITE_OPEN_READ_ONLY|NO_MUTEX`、`query_only=1`、WAL 已提交快照），不取 `writer.lock`、不迁移 schema、不占全局 Mutex；`_writer_lock` 改为 `Option`。配套 `Store::root()`、`SharedStore::root()`、`SharedStore::open_handle_count()`（只锁 handles map，用于缓存展示一致性门控）。

只读句柄要求库已是当前 schema（v28）且 WAL；版本不符会明确报 "state database is not at the current schema; reopen it with Store::open"，不会就地升级。

### 2. 四个查询热点

- `sync_issues`：候选集改为 4 支 UNION（conflict 走 partial 索引；dirty drafts；uncertain operations 走 `operations_node`；namespace_ops 三态走 `namespace_ops_node`），外层保留 `id>?1 ORDER BY id LIMIT 257` 游标语义，逐 id 详情逻辑不变。partial 索引用字面状态谓词 + `INDEXED BY` 锁定（SQLite 无法从 `state='uncertain'` 推出 partial 谓词，且无 ANALYZE 统计）；索引改名会让查询 fail-loud，由 `tests/schema_indexes.rs` 与迁移测试守护。
- `downloads_needed`：3 支索引化候选（stale cached 走 `nodes_cached`；pinned 子树递归走 `nodes_pinned` + `nodes_parent_name_live`；下载意图走 `transfers(node,version,direction)` 唯一索引前缀），再统一原有过滤与逐候选判定；输出语义不变。
- `desktop_status_seeds_for(roots)`：一条递归 CTE 取 roots 子树 + 祖先链（tree-first `CROSS JOIN`、`scope MATERIALIZED`，复用同一组 `SEED_COLUMNS`/`SEED_FILTERS`）；namespace 根命中 fast-path 回退全量，避免整树随机查找。
- `cache_candidates`：单条集合式 SQL 一次物化 pinned 子树、upload_blocked 子树、engine pending、operations/local_creations 节点、blob 保护与共享集合、dirty drafts、access_blocked；Rust 侧只保留 active 集合、打开句柄、最近 60 s 发布与 `symlink_metadata`。保护语义与 `cache_usage`/`trim_cache` 签名不变，旧实现保留为 `#[cfg(test)]` 对照。

### 3. 桌面读路径与上传/缓存循环

- GetIssues/GetStates/GetCacheSettings 优先在只读句柄上执行，打开/查询失败回退原加锁路径（fail-safe）；JSON schema 与错误串逐字不变。GetCacheSettings 的锁外 `cache_usage` 仅在 `open_handle_count()==0` 时使用，保证 protected/reclaimable 与 trim 保护集一致。
- `upload_loop`：确认上传后不再等 1 s，背靠背排空本 burst 新入队 op；`refresh_cached` 按进展门控（无进展立即、有进展置 pending 且空闲 ≤1 s 或最迟 5 s 补跑、retry_due 必跑）。`#14/#17` 的 uncertain 上传预算/退避未动。
- `cache_loop`：保留 15 s，trim 门控（策略 dirty / limit 变化 / pressure / 60 s 去抖），修掉「策略变更但 local_revision 未变被 skip」的既有缺陷。

### 4. 增量状态投影缓存（issue #8）

`crates/drive-runtime/src/status_cache.rs`：后台单线程独占 `SharedStore::take_notifications`，维护内存 committed `StatusProjection`（`StatusSeed` rows + children）：

- 启动：领取通知 → 短 Store guard 取 `status_change_watermark` → 只读连接全量扫描 seeds → 从 cursor 幂等回放 journal 追平 → 发布。
- 增量：每页 ≤512 条 journal，在同一个短 Store guard 内解析事实变化（点查 `desktop_status_seed`、位置键 `desktop_status_ids_at` + 点查、子树失效一次 `desktop_status_seeds_for` 增量重读），批次应用后同 guard `prune_status_changes`；发布节流 250 ms（working clone 成新 Arc → swap → 旧 Arc 锁外 drop）。
- 重建仅限 journal 缺口/溢出/epoch、积压>50k、增量超 `MAX_CACHED_NODES=500_000`、受影响子树>50k 或 namespace 根（异步重建，继续服务旧快照）。空闲退避 250 ms→1 s；stop-aware `try_lock` + 重建中断点，`Tasks::join` ≤2 s；订阅失败/超限永久 disable，`snapshot()` 恒 None。
- 桌面接入：`StatusTree` 支持 `Loaded`/`Projected` 双来源，`load_with_projection()` 与 `load()` 逐字段等价（缺根/祖先链→Err）；`states_off_lock` 优先投影，Err 回退权威 scoped 读，None 走原路径；文件类快速路径、256 上限、preview、错误串、JSON 不变。
- drive-core 新增 `desktop_status_seed(id)`、`desktop_status_ids_at(parent,name)`，可在 `query_only` 连接执行。
- **增量失效（对抗验证修复）**：① 目录由「隐藏」变「可见」（overlay remote-parent 恢复、目录移出 `access_denied` 子树）也判子树失效，否则后代永久缺失；② 同页子树 walk 删除循环加 `seen` 保护，避免「目录移动 + 后代移出」同页时已点刷新的行被 `None` 覆盖；③ `access_denied` journal 来源先按受影响闭包 scoped 重读（#25 `desktop_status_acl_refresh`，`SUBTREE_APPLY_LIMIT=50_000`），仅在超限或查询不可用时回退全量 `Batch::Rebuild`（ACL 视图含 overlay remote-parent 边，scoped 查询覆盖不完整时的 fail-safe）。

未接入 `status_index::IndexOwner`（availability/transient 内容核验成本高）；目录聚合增量（`status_aggregate` 的 Summary 树）留待后续。

## 边界

- 数字来自合成夹具 + 本地文件系统 + 进程内 FUSE，**无真实 NAS、无真机 GUI**；rchar 为进程级读字节，不代表 NAS 吞吐或 GUI 帧率。
- 本机基线 states_root 469 ms，p0 记录的 980 ms 不可在本环境复现；门槛 1 在 baseline 也能通过，修复有效性的证据是相对比值、混合超时与持锁响应。
- namespace 根 `GetStates` 仍为 O(节点) 内存/读量；最终合并树中 `GetTransfers` 仍取全局 Store 锁；`GetOverview` 稳态走只读连接（`desktop.rs overview_measured`，只读打开失败才回退 writer 锁）、`GetInitialization` 完全独立（只读初始化进度快照，不取 Store/control 锁）、`GetDirectory` 仅页面快照段持 writer 锁（#23/#30）。210k 持锁测试中 overview 1500–1900 ms 是 #21 合并前旧树数据，不再作为现状。
- `sync_issues` 候选 UNION 无 per-branch LIMIT（极端候选多时先物化再截断）；`pinned` 命名空间根时 `downloads_needed` 仍遍历子树；每次新建只读连接的成本约 0.55 ms 指 `Store::open_read_only` 打开连接（不含查询）；最终树 GetStates/GetIssues/GetOverview 各 1 条只读连接，GetDirectory 复用页面快照后为页面段 writer 锁 + 1 条只读连接（#30）。
- 增量投影接受 committed 快照略旧：发布节流 250 ms；权限变更自 #25（`d87505b`）起按受影响闭包 scoped 重读（`status_cache.rs desktop_status_acl_refresh`，`SUBTREE_APPLY_LIMIT=50_000`），仅在超限/查询不可用时退回整页 `Batch::Rebuild`；旧版整树重建基线 468.7 ms / rchar 1.25 GB（294k 合成夹具，`scale_perf`）；其余权限最多滞后一个发布周期；`>500k` 节点禁用回退；内存约 250–350 MB@294k（两代投影 + 克隆瞬时）。
- 投影无公开观测接口；验收用 cold/warm 时序与持锁探针间接证明。增量失效的 e2e 状态注入需要 scratch-only SQL seam：本轮以对抗副本 + in-tree predicate/查询语义单测覆盖（H1/R1/R2 正由此发现并修复），产品树暂未加 feature-gated seam，未来改 read_batch 接线时可能缺 e2e 回归。
- 单页 journal 处理在单个短 Store guard 内完成，未对最坏页持锁时长设硬预算/埋点。
