# Drive Native .9：FSearch 提速与问题恢复操作

开发版 `0.1.0~dev20261103.9`，面向 Ubuntu 24.04／Mint 的后续试用。源代码冻结为 `dfb5aca4bf571f35ade337395ba15c761cc55075`，数据库 schema23、IPC20 与 `.8` 相同。

## 本次改善

- 减少 FSearch 扫描时重复的元数据查询与对象构造；复用已准备的 SQL、目录完整性索引和有界目录视图。
- 修复目录项与属性 TTL 反序传递，保留路径重新核验。正目录项 TTL 为 0；完整且已确认内容的属性 TTL 默认 1 秒。通知丢失时降低缓存复用，权限与目录预览检查保持有效。
- 修复无关的待处理删除阻断所有普通上传：按文件身份、父目录依赖和路径重叠判断阻塞，保留未知提交核对。
- 问题界面增加具体处理说明、重新核对／重连、打开可用父目录、复制脱敏诊断，并保留暂停、登录及设置入口。按钮异步执行；后台忙时明确提示重试，接受核对请求不等于问题已解决。

## 实测结果

使用原版 FSearch 0.3.1 和普通 release 二进制，在独立 WSL Ubuntu 24.04 窗口进行三轮交替扫描。下面是中位耗时：

| 合成目录范围 | `.8` | `.9` | 同窗口本地 ext4 |
|---|---:|---:|---:|
| 102130 条目，首次扫描 | 74.97 秒 | 10.34 秒 | 0.52 秒 |
| 同范围重扫 | 67.40 秒 | 11.14 秒 | 0.52 秒 |
| 319679 条目／56073 目录，首次扫描 | 未测 | 59.43 秒 | 1.77 秒 |
| 同密集目录重扫 | 未测 | 56.52 秒 | 1.77 秒 |

首组较 `.8` 缩短约 86%／83%。30 次完整扫描均通过保存索引的条目、重复项、属性真值检查，正文下载次数为 0。合成目录不等于真实 Personal_Sync；没有清空宿主页缓存，不称磁盘冷读结果。密集目录仍远慢于本地，issue #5 保持开放。

## 验证和升级

888 项 Rust、117 项 GUI 回归通过；debug／release 各 31 项显式 FUSE 和 1 项 runtime 内核回归通过。独立诊断构建还验证了原版 FSearch 活动扫描中止、重新扫描、文件编辑和另一挂载继续访问；它不参与上述主要计时。

既有隔离 Ubuntu 24.04 环境中，`.8 → .9` 的实际暂停升级、Qt 后台接管、安装版恢复接口、GUI 单实例、同版重装、purge 后保留数据及再安装读取均通过。两份未上传草稿、待处理操作和明确的修改时间意图保留；旧 `.8` 配对二进制也成功读取同 schema23 数据。本次没有执行已安装软件包降级，也未覆盖升级中的未知提交或活跃初始化任务。

安装后在任务界面选择“应用后台更新…”，按提示先保存并关闭正在编辑的文件。升级会暂停并正常切换后台，保留任务和未上传数据；确认新后台后按需恢复同步。不要通过清缓存处理升级或同步错误。

## 范围

本轮没有连接 NAS、读取凭据或改动真实个人文件。原生 ACL 的逐目录写权限（#7）、原账号积压队列恢复、Personal_Sync 完整初始化、普通目录全同步、Mint 桌面和长期数据安全验收仍未完成。本包是开发版，不是 rc1；旧长期目标保持暂停。
