# P1 架构修改契约与配套实现

2026-10-31。基于冻结 `.6`（源码 `62be13c9f9f4a2457a3040829f478bf43b1821df`）的热点测量与当前公开源码核对；desktop.rs/desktop_tree.rs相对冻结提交有后续排版，引用的是实际调用行为而非行号相同。本文件确定队列、目录和状态结构的后续修改边界；原生等待配套修复单独记录，尚未达到P1性能目标；进入条件仍由[验收门槛](../DELIVERY_GATES.md)决定。按2026-10-31用户修订，允许P0独立24小时窗口继续运行时开展隔离开发；P0仍须完整审查后才可通过。现有原生事件、上传确认、身份/版本条件及持久性规则不重写。

## 已确认问题与应保留机制

| 路径 | 当前源码事实 | 修改边界 |
| --- | --- | --- |
| [FUSE本地队列](../crates/drive-fs/src/lib.rs) | 四线程、256项有界队列；目录、元数据、缓存读取均排入其中。网络等待另有队列 | 不能只增加线程数：等待Store锁的任务仍会占满本地线程。已打开完整内容读取需要独立通路 |
| 同文件中的readdir | 忽略fh，每页重建全部条目，offset只在最后遍历时使用；EOF也重建 | 目录句柄持有稳定枚举视图，后续页和EOF不再查询整目录 |
| [Store::children / record_impl](../crates/drive-core/src/filesystem.rs) | 子项逐个生成完整FileRecord；涉及多次SQL、草稿/正文属性和状态；首次还分配inode | 目录项专用投影只含稳定身份、inode、类型、名称；不能把完整属性路径重命名后照用 |
| [desktop::states](../crates/drive-runtime/src/desktop.rs)、[StatusTree](../crates/drive-runtime/src/desktop_tree.rs) | 每批请求在Store锁内读全树种子并取得细节，然后在锁外递归聚合；children还克隆列表 | 改为长期保留的派生索引，状态查询读取结果；不能以更长TTL掩盖全树重算 |
| [local_revision](../crates/drive-core/src/filesystem.rs) | SQLite total_changes；inode分配和其他非状态写入也计数，回滚可产生通知假阳性 | 保留其既有粗粒度通知用途；另建提交后变更批次，不能据它推断节点差异或服务器游标 |
| [ReadHandle](../crates/drive-core/src/state.rs) | 已有按blob计数、不可变文件句柄和Drop减引用 | 复用它，不能为新读取通路另造不一致的引用表；状态查询不要短暂打开所有内容来确认可用性 |
| [write/fsync/release](../crates/drive-fs/src/writable.rs) | 草稿写入与checkpoint保留本地保存边界 | 队列拆分必须保留同句柄的写入/截断/fsync次序，以及停止期间旧句柄保存的已验证行为 |

## 修改顺序与交付单元

### 原生等待恢复的配套修改（隔离源码已接入，真实联调待验）

原 `.6` 基线和 `.2` 发布包的 `wait_changes` 与事件 IPC 总期限均为450秒。独立分支已将两层改为接收进度驱动的空闲期限；实现及实网覆盖缺口见[原生通知期限](NOTIFICATION_IDLE.md)。[工作进程退出前诊断](CONNECTION_DIAGNOSTICS.md)已完成本地回归与有界只读观察。已打开文件的读取队列与句柄锁隔离现已实现，见[实现范围](FUSE_READ_ISOLATION.md)。目录句柄、增量状态及其余缓存结构仍待实现，P1性能目标未通过。

修改前后覆盖：超过旧总期限但持续收到合法数据、单个长轮询合法等待、完全静默、部分帧后停滞、keepalive、EOF、取消及随后连接复用。先用模拟时间和传输夹具验证，再在独立只读 NAS 实例核对；原冻结基线保持不变。停止时保留可诊断的原始退出分类，再执行清理，避免把清理阶段的强杀当成断连原因。以上为当前源码核对后的实现约束，不是已通过的协议或恢复测试。

### A. 分离完整内容读取和元数据调度

先将已打开Cached和Draft读取从元数据队列分离。FUSE分发仅完成有界句柄定位、请求登记和提交；复制Arc后释放句柄锁，再做本地IO。缺失内容继续进入现有可取消下载路径，保留同版本请求合并和其他读取者需求。打开未就绪文件不在分发线程等网络。

本地读池、元数据池和网络等待池分别记录队列长度、排队时长及运行时长。以固定线程/队列预算做基准，不靠无界spawn或无限队列换取低延迟。提交失败仍必须给出明确错误，不能返回空正文。写入请求按字节统计占用；现有256项乘以1MiB写入上限本身可接近256MiB，不能仅按任务数量宣称满足内存目标。具体容量由同条件压测决定，不能把新增过载失败从统计中剔除。

必须保持：读取消恰好回复一次；关闭与正在读取并发时Arc保护内容；缓存驱逐不能回收打开内容；Draft读/写/截断同步采用同一文件规则。持有句柄锁时不进入Store或等待IO；Store持锁路径不得反向取得FUSE句柄表锁。已有Store→blob引用表顺序保留，不能引入blob引用表→Store反向路径。

### B. 目录句柄与轻量目录项

实现opendir/readdir/releasedir独立句柄表。建立视图时取得该目录的可见条目和稳定inode，按既有name/id排序；保留分层权限、删除标记和local_creations遮蔽规则。首次inode分配批量事务化，不改变已有inode，正文状态不参与目录项投影。

目录cookie指向同一视图中的下一项；缓冲区满时只推进已返回项，EOF不重新查库。支持seekdir/rewinddir以及多个独立目录句柄。打开期间新增/改名/删除允许旧句柄继续列出其打开时视图，新句柄取得新视图；后续lookup/open仍由权威身份及权限核验，不能让旧目录项绕过权限检查。不能把该枚举规则扩展为文件内容旧版本保证。

视图按目录版本共享引用并按字节计账；release后可回收，旧视图不可被新版本就地修改。大目录视图和大量同时打开目录必须测内存预算；如果改为分段存储，仍必须保持cookie稳定，不能一边翻页一边无约束读取变化中的OFFSET集合。不设置长期属性TTL替代内核失效通知。

### C. 提交后变更批次与增量状态

SQLite继续是唯一持久权威。派生索引随fsd生命周期重建，不独立成为上传/删除判断依据。每次成功的本地事务在释放Store串行写入边界前发布有序变更批次；回滚不发布。批次包括受影响身份、旧/新父身份、语义类别和连续序号。未知写入、日志溢出或序号缺口使派生索引进入重建，不能继续报已同步。进程崩溃时索引一起丢弃，启动按数据库重建，因此无需另造一份持久同步数据库。

实施前逐一登记以下变更入口，不以“最常用的几个调用点已通知”代替覆盖：

| 数据变化 | 必须失效/重算的范围 |
| --- | --- |
| 原生事件、快照安装、访问限制 | 改变的身份、旧/新祖先；全量安装或权限批量变化允许有界重建 |
| 下载发布、失败/重试、传输开始结束 | 文件自身、祖先聚合；运行中传输还需独立瞬态序号，不只看SQLite |
| 草稿创建/修改/checkpoint、上传确认、冲突解决 | 对象的本地完整性、pending/conflict、版本及祖先 |
| 创建/重命名/删除、namespace_overlay与local_creations | 旧父和新父，以及被遮蔽/重新可见对象；同名不同身份不得共用状态 |
| 固定/取消固定 | 规则节点及其受影响子树的继承属性；不能声称此类变更恒为O(树深) |
| 释放/驱逐、内容丢失 | 本地完整性和祖先offline计数；本地缺失不可继续报离线可用 |
| inode、LRU访问记账等非语义写入 | 不触发全树状态重建；现有粗通知可以合并 |

普通单文件状态变更只更新自身和祖先。用每种状态的子树计数维护优先级，保留现有conflict、pending、失败/重试、updating/downloading、pinning及完整状态的顺序；offline_available、pinned、服务器同步状态独立记录。空目录、继承固定和错误详情代表项都要有确定规则，不能只有一个最高优先级状态而丢掉计数。

索引保存紧凑身份映射、父关系、状态与计数；不为每批请求克隆整树。状态查询所需路径解析也来自同一已发布代次，防止“旧身份/新聚合”混配。瞬态下载叠加必须先更新聚合再通知桌面，避免全树变更信号触发重复重建。查询不能调用open_cached或正文IO；内容可用性由实际发布/释放、启动核对及IO失败事件更新，不能假设任意外部删除文件都自动产生数据库变更。

启动重建仅允许一个构建者，按固定块和可观测时间预算运行；读到一致的SQLite快照，保存起始序号并补齐构建期间已提交批次，最后原子发布。不得分页读取不同代次却标为一致快照。缺口则丢弃候选重建；旧快照可以显示明确未确认状态，不能冒充当前已同步；权限收回必须及时阻止后续访问。现有API若没有可表达重建状态的字段，先用明确local-state错误；新增状态需同时更新GUI/Nemo和接口兼容测试。

批次覆盖审计与纯状态机随机序列测试是接入前置条件。首次版本可保留批量计算作为测试oracle和明确重建路径，但不能在正常每次图标查询时回退扫描全树。

### D. 缓存管理与退出边界

复用现有按版本下载合并、ReadHandle引用保护、固定/脏写/冲突保护，补所有新路径的引用计数测试。累计缓存容量在提交/释放时更新，真实删除成功后才扣除磁盘占用；启动核对、孤儿回收与日常查询分开。不得把LRU访问记账当作语义状态变化导致全树重建。

将停止请求、网络停止、路径卸载、旧句柄排空分别诊断。已验证正常lazy detach后旧可写句柄可以fsync并在重启后恢复；不能通过关闭FUSE连接或强杀来宣称修好退出卡顿。具体超时与强制卸载策略需结合持久性测试决定，不能在P1里未经验证改变已确认保存契约。普通网络worker恢复始终不卸载FUSE。

MFM的450秒原生请求截止问题已有独立协议证据，不混入队列/聚合重排，以免同条件前后比较失去归因。该修复必须单独绑定原生等待、保活、取消及重连验证，不把拉长固定截止直接等同于官方进展超时。

## 验证与发布条件

每个单元保持独立提交；适用回归和同条件对比通过后，按目标§9.1发布开发包，不攒到阶段末。仅设计/测试补充不单独打空包。

1. A：固定21万节点、2000子目录项、48路混合负载；分别测已打开句柄读取和重新打开读取。报告队列等待/执行、p50/p95/p99/max、所有错误和超时；读快了但目录/写入饥饿不算通过。
2. B：跨多页及EOF、seek/rewind、并发目录改名/删除、权限过滤、新增与同名重建。对照每次枚举实际数据库投影次数，证明后续页未重建；测大量目录句柄的释放和内存。
3. C：同一随机事件序列对比旧批量oracle与新聚合；包含回滚、旧/新父、重复事件、错误清除、继承固定、活动下载、快照切换、权限和重建期间变更。单文件变更只触及祖先的计数由测试断言；固定整树等批量操作另测，不伪装成常数复杂度。
4. D：已打开旧版本、取消一个读取者仍有其他需求、固定新子项、释放空间不删NAS、未上传/冲突/旧完整版本保护；正常停止后fsync及重启回归。涉及数据安全的改动需要对应故障证据，普通生命周期不替代P3。
5. Rust、GUI及显式FUSE内核测试全部运行，沿用`mounted.rs`中的随机写/截断、同名重建、原子替换及离线树测试，不能把ignored当通过。新增测试覆盖实际行为，避免只镜像实现。
6. 对比保持原.6独立状态、相同预热/数据/负载/超时/测量口径；诊断插桩版不作为发布性能结果。RSS含fsd/worker口径，除稳定平台外还检查瞬时峰值、FD、线程和队列字节。启动重建和长期稳定另列。

性能门槛仍是目标中的2000项目录p95≤300ms、21万节点GetStates≤500ms、48路混合≤1s且零超时、缓存小文件p95≤50ms、约20万节点RSS≤300MB。此计划没有验收数据，不降低门槛，也不意味着仅凭上述结构一定达标。
