# Drive Native .20261109.1：并发、锁与存储性能修复（#21–#34）

开发版 `0.1.0~dev20261109.1`，面向 Ubuntu 24.04／Mint 的后续试用。发布源提交为 `da68c15584d9eabecbf1a6158941da15d22593b4`（`integration/fixes2` 全量修复树 `9cb6b1c` 的发布准备提交，代码内容与 `9cb6b1c` 一致，差异仅为 `debian/changelog` 发布条目与本文档），数据库 schema28、IPC21。本版一次性合入 #21–#34 的读取路径、写入路径、存储与桌面修复：48 路混合负载超时从 28 降到 **0**，`GetOverview` 不再占用全局 Store 锁，只读打开不再写库，100 MiB 顺序写的 fsync 从 817 降到 18。

## 本次改善

- **读路径与全局锁（#21/#23/#30）**：`GetOverview` 改走私有只读 WAL 连接，昂贵的计数按已提交代次缓存、JSON 在锁外组装；opendir 的目录投影在 Store 锁外构建，锁内只做轻量校验；`GetStates` 的 detail 查询批量化，`GetDirectory` 复用页面快照，不再重解析/重序列化路径。
- **只读打开与 NamespaceIndex（#22）**：只读 open 不再持久化缓存最近使用记录（改为内存缓冲批量落库），不再触发 WAL fsync；NamespaceIndex 新鲜度由命名空间语义水位驱动，失败时保留旧代并退避重试，不再整代重建或降级为空代。
- **写路径（#24）**：draft 元数据按 dirty epoch 合并提交，draft 文件 fsync 移出 Store 锁，SETATTR(mtime) 不再额外 fsync；100 MiB 顺序写的 row change 从 3200 降到 4、fsync 从 817 降到 18。
- **状态投影与信号（#25/#27/#31）**：status cache 单页持锁有硬预算、积压主动让出，发布改为不可变 base + 稀疏 delta；5 条永久 disable 路径改为可观测、可自动恢复的 degraded 状态；首装补发按代折叠为一条失效消息；fd 状态用 `SharedStore::change_state()` 语义水位驱动，新增 revisioned `StatusChanged2` 变更集，worker 改排队/背压，download retry 改事件驱动。
- **ACL 与 remove barrier（#26/#28）**：`access_blocked` 闭包改祖先上溯 + 权限判定缓存，READDIRPLUS 权限工作批量化并按 128 项分页；未完成 remove 的 barrier 改为内存索引 + TEMP 版本簿记，10k 积压的稳态 barrier 从 236 ms 降到 0.016 ms。
- **GUI 放大（#29/#31）**：窗口/管理器/问题页查询按 1 秒窗口 single-flight + 尾随合并，文件页不再因 overview 清空重载，图标按差异复用；GUI 消费 `StatusChanged2`，status-only 变更不再触发 GetOverview。
- **存储与 schema v28（#32）**：7 个索引（operations 计数/节点/内容/核对候选、inbox 待处理、sync_history 触发/结果游标）+ retention（operations/namespace_ops/inbox 有界清理，且不推进 journal）+ 安装快照/上传祖先查询批量化；v27→v28 是唯一迁移路径，升级前自动 `VACUUM INTO` 备份。
- **远端与初始化（#33）**：同父目录的 remove/upload 回读复用一次父目录枚举，native 连接池按用途分 lane 并设有队列上限与等待超时，事件页序列化/SHA-256 去重。

## 实测结果

在 workstation202611（32 核／125 GiB，Ubuntu 24.04，内核 6.8.0-147）上，对与发布源代码相同的合并树做专项实测：

| 项目 | 结果 | 口径 |
|---|---:|---|
| 48 路 mixed 负载超时 | **0**（p95 861.6 ms，max 1.64 s） | `latency-clean-driver.log`，classic 场景 0 超时 |
| 210k 合成树 GetStates p95 | **226.95 ms** | SLO 500 ms（发布前 `.1` 树 312.9 ms） |
| 2000 项目录列举 p95 | **3.89 ms**（Store）／0.53 ms（FUSE） | SLO 300 ms |
| 持有 Store 锁 2 秒时 GetStates／GetIssues | **245／248 ms** | 旧线约 2352 ms |
| GetOverview 总耗时 p95／持锁 | **0.708 ms／0 ms**（read-only 40/40） | SLO 500 ms／200 ms |
| 只读 open 的 WAL 写入／NSI 重建 | **0／0** | 100k/319k/369k 重建均在预算内 |
| 100 MiB 顺序写 | **4 row changes／18 fsync**（37.85 ms） | before 3200／817 |
| 未完成 remove barrier（10k 积压） | **0.016 ms** 稳态（首建 45.8 ms） | before 236 ms |
| ACL lookup p95（50k denied） | **21.3 µs** | before 95.6 ms；256 路径批 3.9 ms |
| READDIRPLUS 2000 项 | **12.6 ms**（代理口径；5k 13.7 ms） | before 326 ms |
| 1M 行 pending_operations | **0.0014 ms**（partial index） | before 46.3 ms（SCAN） |
| schema v27→v28 升级（294k 节点） | **614 ms**（备份 169 ms） | 一次性迁移 |
| GUI 每个状态信号 | **0 次 GetOverview** | before 1 次 + 全量重排 |

48 路 mixed 与 overview 的结论来自 210k 夹具的干净窗口复跑；状态查询、目录列举与锁交接同时满足 SLO。以上均为合成夹具与 lab FUSE 口径，没有真实 NAS、真实桌面会话或长期数据安全验收。

## 验证和升级

发布包由 `dpkg-buildpackage -b -us -uc -j4` 在干净 `git archive` 树上构建（测试未关闭）：workspace all-features 1176 通过／0 失败／59 忽略（63 个套件），GUI 24 套／276 项通过；default-features 在最终验收树 1166 通过／0 失败／54 忽略。`scripts/verify.sh` 退出码 0，lab `--simulate` 报告 `passed=true`、`LocalComplete`。包内容核对通过：三个 native 二进制、GUI onedir、`/usr/bin/drive-native` 包装、4 个 systemd user units、Nemo／Nautilus 扩展与 gio probe 齐备；`SOURCE_COMMIT` 与 `BUILD_VERSION` 与源一致，包内没有 docs/validation 证据、.git 或密钥材料。

schema 由 24→25→26→27→28 累积演进（28 = #32 的 5 个 partial 索引（operations 计数/节点/内容/核对候选与 inbox 待处理）+ 2 个 `sync_history` 序号索引（触发/结果游标）+ retention 历史裁剪 + 批量点查/上游祖先查询批量化；27→28 为唯一迁移路径）。FSD 与 worker 必须成对更新，旧程序不能读取新 schema。升级时先在任务界面选择“应用后台更新…”，按提示保存并关闭正在编辑的文件；升级会暂停并正常切换后台，保留任务、未上传修改和同步历史。不要通过清缓存处理升级或同步错误。

本构建机没有可用的 chroot/debootstrap，因此没有执行真实 dpkg 安装／升级／卸载验证；本版对安装流程的结论止于包内容与元数据层，真实 Mint／Cinnamon 桌面验收也未执行。kernel FUSE 测试需显式串行并设置 `DRIVE_NATIVE_FS_DIAGNOSTICS=1`（并行 + 诊断环境变量 OnceLock 的测试隔离问题，非产品回归）。
