# 同步问题的安全恢复入口

问题中心把连接状态、待同步状态与恢复动作分开显示。`GetIssues` 条目即使没有 `can_keep_both`／`can_keep_directory`，也会按原因显示检查目录、权限、占用应用或本机存储的具体下一步。

- **重新核对 / 重连**：仅在 `GetOverview.recovery_actions.recheck_issues=true` 时调用异步 `RecheckIssues`。请求接受不等于已解决；保持用户暂停，不重置未知提交为可重发。核对后无依赖的正常操作可以继续同步。
- **保留双方版本**：只使用当前条目允许的 `KeepBoth`／`KeepDirectoryBoth`，携带当前版本令牌。不提供强制标记完成、删除草稿或清空缓存按钮。
- **打开可用父目录**：通过异步、本地 `GetDirectory` 从父路径逐级核对，最多33次。未就绪预览不能冒充空目录，超时停止并允许重试。GUI线程不 `stat`／`resolve` FUSE路径，也不为定位触发正文下载；失效会话和隐藏窗口的迟到结果不打开路径。文件管理器不接受请求时明确报错。
- **复制诊断**：复制封闭状态／原因枚举、布尔与有界计数；不包含路径、账号、版本令牌、凭据、文件正文或原始后台错误。不把该摘要冒充完整日志导出。
- **暂停并保留数据**：异步调用当前任务 `Pause`，收到成功回执才显示已暂停。恢复同步仍是任务页的独立明确操作。

主窗口将 `upload_block` 作为独立提示展示，并提供进入问题中心的按钮；已连接不能遮蔽上传阻塞。NAS可控路径和错误文本使用纯文本显示。旧后台缺少恢复能力字段时不发送未知方法，保留刷新、复制诊断、暂停和登录入口。

[恢复界面回归](tests/issue_recovery_gui_tests.py)通过合成异步回调验证按钮、暂停意图、未知提交保护、路径边界和诊断脱敏；由原 [conflict_gui_tests.py](tests/conflict_gui_tests.py) 纳入完整GUI套件。真实D-Bus、安装包和NAS恢复仍须单独验证。
